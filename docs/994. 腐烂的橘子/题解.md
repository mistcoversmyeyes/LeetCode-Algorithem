[994. 腐烂的橘子](https://leetcode.cn/problems/rotting-oranges/solutions/)
====

# 题目描述

在给定的 `m x n` 网格 `grid` 中，每个单元格可以有以下三个值之一：

- 值 `0` 代表空单元格；
- 值 `1` 代表新鲜橘子；
- 值 `2` 代表腐烂的橘子。

每分钟，腐烂的橘子 **周围 4 个方向上相邻** 的新鲜橘子都会腐烂。

返回 *直到单元格中没有新鲜橘子为止所必须经过的最小分钟数。如果不可能，返回 `-1`* 。

**示例 1：**

```
输入：grid = [[2,1,1],[1,1,0],[0,1,1]]
输出：4
```

**示例 2：**

```
输入：grid = [[2,1,1],[0,1,1],[1,0,1]]
输出：-1
解释：左下角的橘子（第 2 行， 第 0 列）永远不会腐烂，因为腐烂只会发生在 4 个方向上。
```

**示例 3：**

```
输入：grid = [[0,2]]
输出：0
解释：因为 0 分钟时已经没有新鲜橘子了，所以答案就是 0 。
```

# 思路一：多队列BFS（❌ 过度设计）

## 解题思路

**核心思想**：为每个初始腐烂的橘子维护一个独立的BFS队列，每个队列独立扩散，按分钟推进。

**我的最初想法**：
> "呃首先我注意到这个题目中没有说明腐烂的橘子总共有多少，那我可以假定开始的时候有多个腐烂的橘子对吗？"

确认可以有多个腐烂源后，我第一反应是：
> "对于每一个腐烂的橘子都需要维护一个BFS的队列，然后用一个大循环，在这个循环内部呢，我们按照一定的顺序对每个队列进行更新。"

**算法流程**（设想的，未实现）：
1. 遍历网格，为每个腐烂橘子创建一个队列
2. while 还有非空队列：
   - 按顺序处理每个队列的一层
   - 将新腐烂的橘子加入对应队列
3. 所有队列为空时结束

## 问题/优化方向

**致命缺陷**：过度复杂化！

面试官的引导让我意识到：
> "这有必要吗？为什么一个队列就够了？"

**关键洞察**：
- 多个腐烂源同时扩散，本质上和单个源是一样的
- BFS的"层"概念天然适合表示"分钟"
- 把多个源点一起入队，它们会自然地在同一层被处理

# 思路二：单队列多源BFS（✅ 推荐解法）

## 解题思路

**核心思想**：用一个队列管理所有腐烂源，层序遍历模拟每分钟的同时扩散。

**恍然大悟时刻**：
> "把它们看成单源就行了，因为每一次清空队列的时候都是将当前时间已经到达的格子清空，所以无论是单源还是多源都一样。"

**为什么一个队列可以处理多源？**
```
初始状态：
2(0,0)  1       1
1       2(1,1)  1
1       1       1

第0层队列：[(0,0), (1,1)]  ← 两个源一起入队
第1层队列：[(0,1), (1,0), (1,2), (2,1)]  ← 同时扩散
...
```

两个腐烂源到达同一个橘子？先标记的那个会继续，后到的发现已经是2就跳过——幂等操作保证正确性。

**算法流程**：
1. **初始化**：遍历网格，统计新鲜橘子数量 `fresh`，将所有腐烂橘子坐标入队
2. **边界情况**：如果 `fresh == 0`，直接返回 0
3. **BFS层序遍历**：
   - 记录当前队列大小 `size`（当前层的节点数）
   - 处理 `size` 个节点，每个节点向4个方向扩散
   - 如果有新鲜橘子被腐烂，`fresh--`，入队，标记 `changed = true`
   - 如果 `changed` 为 true，时间 `minutes++`
4. **返回结果**：`fresh == 0 ? minutes : -1`

## 复杂度

- **时间复杂度**：O(m × n)
  - 每个格子最多被访问一次（入队/出队各一次）
  - 4个方向的常数时间操作
- **空间复杂度**：O(m × n)
  - 队列最多存储所有格子

## Code

```cpp
class Solution {
public:
    bool is_accessable(vector<vector<int>>& grid, int i, int j) {
        if (i < 0 || j < 0 || i >= grid.size() || j >= grid[0].size()) {
            return false;
        }
        return grid[i][j] == 1;
    }

    int orangesRotting(vector<vector<int>>& grid) {
        int cur_time = 0;
        int m = grid.size();
        int n = grid[0].size();
        int fresh_count = 0;

        queue<pair<int, int>> nodes;
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == 2) {
                    nodes.push({i, j});
                } else if (grid[i][j] == 1) {
                    fresh_count++;
                }
            }
        }

        if (fresh_count == 0) {
            return 0;
        }

        while (!nodes.empty()) {
            int size = nodes.size();
            bool has_new_bad = false;

            for (int i = 0; i < size; i++) {
                const auto& [x, y] = nodes.front();

                // 四个相邻方向
                vector<pair<int, int>> adjs = {
                    {x - 1, y},
                    {x + 1, y},
                    {x, y - 1},
                    {x, y + 1},
                };

                for (const auto& [a, b] : adjs) {
                    if (is_accessable(grid, a, b)) {
                        grid[a][b] = 2;
                        fresh_count--;
                        has_new_bad = true;
                        nodes.push({a, b});
                    }
                }

                nodes.pop();  // ✅ 别忘了pop！
            }

            if (has_new_bad) {
                cur_time++;
            }
        }

        return fresh_count == 0 ? cur_time : -1;
    }
};
```

**问题/优化方向**：
- `has_new_rotten` 标记可以简化：直接 `minutes++`，但最后一轮如果没有新橘子会多算一分钟
- 更简洁的做法是：先 `minutes++`，最后返回 `fresh == 0 ? minutes : -1`

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 多队列BFS | O(m × n × k) | O(m × n × k) | ❌ 过度设计，k是初始腐烂橘子数 |
| 单队列多源BFS | O(m × n) | O(m × n) | ✅ 简洁优雅，正确处理多源同时扩散 |

# 关键词与核心洞察

## 关键词

- **多源BFS**：不是"为每个源创建一个BFS"，而是"把所有源一起入队，统一层序遍历"。关键是理解BFS的"层"天然对应"时间步"
- **层序遍历**：用 `size = queue.size()` 记录当前层节点数，确保同一层的节点（同一分钟的腐烂）同时处理
- **幂等操作**：多个源到达同一个格子，重复标记不会导致错误——这是简化多源处理的关键

## Insight

**多源BFS的本质**：

不只是"省几个队列"的问题。更深层次的理解是：**BFS的距离属性**。多源BFS中，每个格子被访问的时间 = 它到最近的腐烂源的距离。这就是为什么一个队列能解决——我们其实在计算"每个新鲜橘子到最近腐烂橘子的最短距离"。

**时间建模的本质**：

"每分钟" = "BFS的一层"。这个对应关系是解题的核心。不是真的去"等待一分钟"，而是用BFS的层次遍历天然地模拟了时间的推进。

## 易错点

- **忘了 `pop()`**：`front()` 取值后必须 `pop()` 弹出，否则队列永不空，导致 TLE（我就是栽在这里）
- **边界条件 `>=` vs `>`**：数组越界检查要仔细，`nx >= 0 && nx < m` 不是 `nx > 0`
- 🌟 **时间计算**：最后一轮如果没有新橘子腐烂，不应增加时间；或者先增加，最后减一
- **初始无新鲜橘子**：`fresh == 0` 时要返回 0 而不是 -1

---

**推荐**：面试中使用**单队列多源BFS**，这是最简洁且正确的解法。重点是理解"多源可以看成单源"这一核心洞察。
