**41.** 缺失的第一个正数 - 题解
====

# 题目描述

给你一个未排序的整数数组 `nums`，请你找出其中没有出现的最小的正整数。

请你实现时间复杂度为 `O(n)` 并且只使用常数级别额外空间的解决方案。

**示例 1：**
```
输入：nums = [1,2,0]
输出：3
```

**示例 2：**
```
输入：nums = [3,4,-1,1]
输出：2
```

**示例 3：**
```
输入：nums = [7,8,9,11,12]
输出：1
```

---

# 关键词与核心洞察

## 关键词
- **原地哈希**：利用数组本身作为哈希表，数字 `k` 存放在索引 `k-1` 的位置。这是解决"O(1) 空间限制"的关键技巧。
- **答案范围压缩**：通过分析发现答案必定在 `[1, n+1]` 范围内，将无限搜索空间压缩到有限范围。
- **时空权衡的极致**：当不能用额外空间时，就复用输入数据本身。这是面试中常见的"限制驱动"思维。

## Insight
- **原地哈希的本质**：不是"省空间"这么简单，而是"理解数据的天然位置"。数字 `k` 有一个天然的家 `index k-1`，我们只是让它回家。
- **为什么答案是 [1, n+1]**：如果数组是 `[1,2,3,...,n]`，答案才是 `n+1`。否则答案一定在 `[1, n]` 中。这个洞察把问题从"无限搜索"变成了"有限检查"。

## 易错点
- **只用 `if` 不用 `while`**：交换后位置 `i` 的新数字可能也需要归位，必须用 `while` 持续处理。
- **死循环陷阱**：条件 `nums[i] != nums[nums[i] - 1]` 必须有，否则 `nums[i]` 和目标位置的值相同时会无限交换。
- **重复数字**：如果有两个相同的数字 `1,1`，没有正确的终止条件会死循环。

---

# 思路一：暴力法

## 解题思路

**核心思想**：从 1 开始逐个检查每个正整数是否存在于数组中。

这是我最自然的想法：对于每个正整数，遍历数组看它是否存在。

**算法流程**：
1. 从 `i = 1` 开始
2. 遍历数组检查 `i` 是否存在
3. 如果存在，`i++` 继续；不存在则返回 `i`

## 复杂度
- 时间复杂度：O(n²) —— 最坏情况下检查 1 到 n，每次检查 O(n)
- 空间复杂度：O(1)

## Code
```cpp
int firstMissingPositive(vector<int>& nums) {
    int i = 1;
    while (true) {
        bool found = false;
        for (int num : nums) {
            if (num == i) {
                found = true;
                break;
            }
        }
        if (!found) return i;
        i++;
    }
}
```

**问题/优化方向**：
时间复杂度 O(n²) 太高，无法满足题目要求的 O(n)。

# 思路二：哈希表（unordered_set）

## 解题思路

**核心思想**：用哈希表存储所有数字，将查找操作从 O(n) 降到 O(1)。

我的改进思路：既然暴力法慢在"查找"，那就用哈希表加速查找。

**算法流程**：
1. 遍历数组，将所有数字存入 `unordered_set`
2. 从 `i = 1` 到 `n`，检查 `i` 是否在集合中
3. 第一个不在集合中的 `i` 就是答案

## 复杂度
- 时间复杂度：O(n) —— 构建 O(n)，查找 n 次 O(1) × n = O(n)
- 空间复杂度：O(n) —— 哈希表存储最多 n 个数字

## Code
```cpp
#include <unordered_set>
#include <vector>

using namespace std;

class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        // 构建哈希表，O(n)
        unordered_set<int> is_in_nums;
        for (int i = 0; i < nums.size(); i++) {
            is_in_nums.insert(nums[i]);
        }

        // 检查 1..=n 里面的数字是否都在数组中
        for (int i = 1; i <= nums.size(); i++) {
            if (is_in_nums.find(i) == is_in_nums.end()) {
                return i;
            }
        }

        return nums.size() + 1;
    }
};
```

**问题/优化方向**：
满足了时间要求 O(n)，但空间是 O(n)，不满足题目要求的 O(1) 常数空间。

# 思路三：原地哈希（✅ 推荐解法）

## 解题思路

**核心思想**：利用数组本身作为哈希表，数字 `k` 放在索引 `k-1` 的位置。

这是在面试官引导下发现的技巧：
- 面试官问："答案的最大值是多少？"
- 我答："如果数组是 `[1,2,...,n]`，答案是 `n+1`。否则答案在 `[1, n]` 中。"
- 面试官问："既然答案只在 `[1, n]`，能不能用数组本身记录哪些数字存在？"
- 我恍然大悟："数字 `k` 可以放在 `index k-1` 的位置！"

**算法流程**：
1. 第一遍遍历：将每个数字 `k` 放到它"应该"在的位置 `index k-1`
   - 只处理 `[1, n]` 范围内的数字
   - 用 `while` 持续交换，直到当前位置的数字归位或无需处理
2. 第二遍遍历：检查哪个位置不对，第一个 `nums[i] != i+1` 的位置就是答案

## 复杂度
- 时间复杂度：O(n) —— 每个数字最多被交换一次到正确位置
- 空间复杂度：O(1) —— 只用了常数额外空间

## Code
```cpp
#include <utility>
#include <vector>

using namespace std;

class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        // 第一遍：原地哈希，将数字 k 放到 index k-1
        for (int i = 0; i < nums.size(); i++) {
            // 持续交换，直到 nums[i] 归位或无需处理
            while (nums[i] >= 1 && nums[i] <= nums.size()  // 在有效范围内
                   && nums[i] != nums[nums[i] - 1]) {       // 避免死循环
                swap(nums[i], nums[nums[i] - 1]);
            }
        }

        // 第二遍：检查哪个位置不对
        for (int i = 0; i < nums.size(); i++) {
            if (i + 1 != nums[i]) {
                return i + 1;
            }
        }

        // 所有位置都对，答案是 n+1
        return nums.size() + 1;
    }
};
```

**问题/优化方向**：
这是满足题目所有要求的最优解法。关键细节：
- `while` 而非 `if`：交换后位置 `i` 的新数字可能也需要归位
- `nums[i] != nums[nums[i] - 1]`：防止重复数字导致死循环

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 暴力法 | O(n²) | O(1) | 最自然，但太慢 |
| 哈希表 | O(n) | O(n) | 工程上完全可用，但不满足题目限制 |
| 原地哈希 | O(n) | O(1) | 最优解，技巧性强 |

---

# 关键要点

1. **答案范围分析**：对于长度为 n 的数组，答案必定在 `[1, n+1]` 范围内。这是解决本题的第一个关键洞察。

2. **原地哈希技巧**：当空间受限时，考虑复用输入数据本身。数字 `k` 的"家"是 `index k-1`。

3. **while 循环的必要性**：交换后当前位置会有新数字，新数字也可能需要归位。用 `while` 确保持续处理直到稳定。

4. **防止死循环**：条件 `nums[i] != nums[nums[i] - 1]` 是必须的，处理重复数字的情况。

---

**吐槽**：这题确实是典型的"技巧题"，正如我在解题时说的："这啥技巧题目，和高中数学喜欢考的那些烂题一个德行。"第一次做绝对想不到，见过一次就会了。类似的原地哈希题目还有 LeetCode 442（数组中重复的数据）和 448（找到所有数组中消失的数字）。

**推荐**：面试中使用**思路三（原地哈希）**，虽然技巧性强，但这是面试官想看到的"满足所有限制条件"的解法。如果是为了工程实践，思路二（哈希表）更清晰、更不容易出错。
