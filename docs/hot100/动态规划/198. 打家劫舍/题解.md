# 198. 打家劫舍 - 题解

---

# 题目描述

你是一个专业的小偷，计划偷窃沿街的房屋。每间房内都藏有一定的现金，影响你偷窃的唯一制约因素就是相邻的房屋装有相互连通的防盗系统，**如果两间相邻的房屋在同一晚上被小偷闯入，系统会自动报警**。

给定一个代表每个房屋存放金额的非负整数数组 `nums`，计算你 **不触动警报装置的情况下** ，一夜之内能够偷窃到的最高金额。

**示例 1：**
```
输入：[1,2,3,1]
输出：4
解释：偷窃 1 号房屋 (金额 = 1) ，然后偷窃 3 号房屋 (金额 = 3)。
     偷窃到的最高金额 = 1 + 3 = 4 。
```

**示例 2：**
```
输入：[2,7,9,3,1]
输出：12
解释：偷窃 1 号房屋 (金额 = 2), 偷窃 3 号房屋 (金额 = 9)，接着偷窃 5 号房屋 (金额 = 1)。
     偷窃到的最高金额 = 2 + 9 + 1 = 12 。
```

**提示：**
- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 400`

LeetCode 链接:
- 国际站: https://leetcode.com/problems/house-robber/
- 中文站: https://leetcode.cn/problems/house-robber/

# 思路一：基础动态规划（O(n) 空间）

## 解题思路

**核心思想**：`dp[i]` 表示前 `i` 间房子能偷到的最大金额。

最开始我想用 MIT 的 DP 方法论来分析这个问题：定义子问题、Guess、Relate、Merge、Solve。但子问题定义是 DP 中最难的部分——"有的时候你定义子问题感觉好像行，但是后面递推的时候越推越不对劲"。

**关键突破：手动填表找规律**

假设 `nums = [2, 7, 9, 3, 1]`，我手动填表：

| i | 房子 | 如果偷这一间 | 如果不偷 | 最大收益 |
|---|------|-------------|---------|---------|
| 0 | 2 | 2 | 0 | **2** |
| 1 | 7 | 7 | 2 | **7** |
| 2 | 9 | 9 + 2 = 11 | 7 | **11** |

**规律浮现**：
- 第 2 间"偷"：9 + dp[0] = 11（偷了第 2 间就不能偷第 1 间）
- 第 2 间"不偷"：dp[1] = 7

**递推公式**：
```
dp[i] = max(偷第 i 间, 不偷第 i 间)
      = max(nums[i] + dp[i-2], dp[i-1])
```

**算法流程**：
1. 初始化 `dp[0] = nums[0]`
2. 处理 `dp[1] = max(nums[0], nums[1])`（特殊情况）
3. 从 i = 2 开始遍历，按递推公式计算 `dp[i]`
4. 返回 `dp[n-1]`

## 复杂度
- 时间复杂度：O(n)，只需遍历一次数组
- 空间复杂度：O(n)，使用 dp 数组存储所有状态

## Code
```cpp
#include <vector>
#include <algorithm>

using namespace std;

class Solution {
public:
    int rob(vector<int>& nums) {
        int n = nums.size();
        if (n == 0) return 0;

        vector<int> dp(n, 0);

        // base case
        dp[0] = nums[0];

        // 状态转移方程
        for (int i = 1; i < n; i++) {
            if (i == 1) {
                dp[i] = max(dp[i - 1], nums[i]);
                continue;
            }
            dp[i] = max(dp[i - 1], dp[i - 2] + nums[i]);
        }

        return dp[n - 1];
    }
};
```

**问题/优化方向**：
- 空间可以优化到 O(1)，因为 `dp[i]` 只依赖于前两个状态
- 第 24-26 行的 `if (i == 1)` 是"特殊情况污染"——可以通过合理定义边界消除这个分支

# 思路二：滚动数组优化（O(1) 空间）

## 解题思路

**核心思想**：计算 `dp[i]` 时只需要 `dp[i-1]` 和 `dp[i-2]`，两个变量就够了。

这是我在面试中被追问后实现的版本：
```
prev2 = dp[i-2]  // 前两间的最优
prev1 = dp[i-1]  // 前一间的最优
curr  = max(nums[i] + prev2, prev1)

然后滚动更新：
prev2 = prev1
prev1 = curr
```

**算法流程**：
1. 处理边界：n = 0 返回 0，n = 1 返回 nums[0]
2. 初始化 `prev2 = nums[0]`，`prev1 = max(nums[0], nums[1])`
3. 从 i = 2 开始遍历，计算 `curr = max(prev1, prev2 + nums[i])`
4. 滚动更新 prev2 和 prev1
5. 返回 prev1

## 复杂度
- 时间复杂度：O(n)
- 空间复杂度：O(1)，只使用常数额外空间

## Code
```cpp
#include <vector>
#include <algorithm>

using namespace std;

class Solution {
public:
    int rob(vector<int>& nums) {
        int n = nums.size();
        if (n == 0) return 0;
        if (n == 1) return nums[0];

        // prev2: dp[i-2], prev1: dp[i-1]
        int prev2 = nums[0];
        int prev1 = max(nums[0], nums[1]);

        for (int i = 2; i < n; i++) {
            int curr = max(prev1, prev2 + nums[i]);
            prev2 = prev1;
            prev1 = curr;
        }

        return prev1;
    }
};
```

**问题/优化方向**：
- 这是最优解，时间 O(n) 空间 O(1)
- 注意：我之前尝试的 `dp[3]` 滚动数组版本有个脆弱判断 `return dp[2] == 0 ? dp[1] : dp[2]`，如果金额为 0 会出错

# 思路三：带 "虚拟边界" 的优雅实现

## 解题思路

**核心思想**：通过定义 `dp[-1] = 0`，消除所有特殊情况分支。

面试中面试官指出：那个 `if (i == 1)` 是多余的——如果把 "第 -1 间房子" 的收益定义为 0，代码会更简洁。

这样递推公式对 i = 1 也成立：
```
dp[1] = max(nums[1] + dp[-1], dp[0])
      = max(nums[1] + 0, nums[0])
      = max(nums[1], nums[0])
```

**算法流程**：
1. 初始化 `prev2 = 0`（虚拟边界，表示 dp[-1]）
2. 初始化 `prev1 = 0`（表示 dp[0] 之前的初始状态）
3. 遍历每个房子，按通用公式计算
4. 返回 prev1

## 复杂度
- 时间复杂度：O(n)
- 空间复杂度：O(1)

## Code
```cpp
#include <vector>
#include <algorithm>

using namespace std;

class Solution {
public:
    int rob(vector<int>& nums) {
        // prev2: dp[i-2], 初始为 0（虚拟边界）
        // prev1: dp[i-1], 初始为 0
        int prev2 = 0, prev1 = 0;

        for (int num : nums) {
            // 当前最优 = max(偷这间+前前一间的最优, 不偷这间=前一间的最优)
            int curr = max(prev2 + num, prev1);
            // 滚动更新
            prev2 = prev1;
            prev1 = curr;
        }

        return prev1;
    }
};
```

**这是最优雅的实现**：
- 没有特殊情况处理
- 代码最短，逻辑最清晰
- 变量语义明确

# 关键词与核心洞察

## 关键词
- **线性动态规划**：`dp[i]` 只依赖于前面固定几项（本题是 dp[i-1] 和 dp[i-2]），这是最基本的 DP 类型
- **滚动数组优化**：当状态转移只依赖前 k 个状态时，空间可以优化到 O(k)，本题 k=2
- **虚拟边界**：通过定义合理的初始值（如 dp[-1] = 0），消除代码中的特殊情况分支——这就是 Linus 说的 "好品味"
- **子问题定义**：DP 的核心难点。"有的时候你定义子问题感觉好像行，但是后面力推的时候越推越不对劲"——需要通过填表、找规律来验证定义是否正确

## Insight

 🌟**关于 DP 的本质理解**：
- **DP 的核心是"状态定义 + 状态转移"，而非实现方式**。记忆化搜索（top-down）和递推填表（bottom-up）是两种等价实现，都避免了重复计算子问题。
- **Bottom-up vs Top-down**：递推需要程序员显式控制状态计算的拓扑顺序；记忆化搜索通过递归栈自动处理依赖关系，对复杂依赖的 DP 更友好。
- **子问题定义没有通用公式**，但有一些启发式套路：
  - 一维不够就加维度（`dp[i][0/1]` 表示状态）
  - 先写暴力递归，再优化
  - 手动填表找规律

 🌟 **关于 DP 分类**：
- **按子问题结构分**: 线性 DP、区间 DP、背包 DP、树形 DP、状态压缩 DP
- **按实现方式分**: 递推(Top-down)、记忆化搜索(Bottom-up)
- 空间优化是独立维度，任何 DP 都可以考虑是否能降维

**关于"好品味"**：
- **"好代码没有特殊情况"**——那个 `if (i == 1)` 是可以消除的
- **变量命名要自解释**：`prev2`, `prev1`, `curr` 比 `dp[0]`, `dp[1]`, `dp[2]` 清晰得多
- **不要依赖巧合**：`return dp[2] == 0 ? dp[1] : dp[2]` 这种判断在金额为 0 时会出错


## 易错点
- **边界处理**：`nums` 为空或只有一间房子的情况
- **滚动更新顺序**：必须先计算 curr，再更新 prev2 和 prev1，顺序错了状态就乱了
- **脆弱的零值判断**：不要用 `dp[2] == 0` 这种判断，金额为 0 是合法输入
- **忘记虚拟边界的威力**：`dp[-1] = 0` 可以让递推公式对所有 i >= 1 统一适用

---

**推荐**：面试中使用**思路三（虚拟边界版）**，代码最短、最优雅、无特殊分支，体现"好品味"。
