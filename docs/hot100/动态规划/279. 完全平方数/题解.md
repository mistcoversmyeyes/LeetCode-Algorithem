# 279. 完全平方数 - 题解

## 题目描述

给你一个整数 `n`，返回**和为 `n` 的完全平方数的最少数量**。

**完全平方数**是指可以表示为某个整数的平方的数，例如 `1, 4, 9, 16` 等。

**示例 1：**
- 输入：`n = 12`
- 输出：`3`
- 解释：`12 = 4 + 4 + 4`

**示例 2：**
- 输入：`n = 13`
- 输出：`2`
- 解释：`13 = 4 + 9`

---

# 思路一：动态规划（✅ 推荐解法）

## 解题思路

**核心思想**：`dp[i]` 表示和为 `i` 的完全平方数的最少数量。

这道题子问题的结构非常清晰，我直接通过"Guess Part of the Solution"的方式猜出了状态定义和转移方程：

> "子问题就是和为 i 的完全平方数的最少数量，dp[i] = min(dp[i - square_1], ..., dp[i - square_k])"

**DAG 视角理解**：
- 每个状态 `i` 依赖于所有 `i - square`（其中 `square ≤ i`）
- 这种依赖关系形成一个有向无环图（DAG），边从小指向大
- 按照拓扑排序（从小到大遍历 `i`），保证计算 `dp[i]` 时所需子状态已计算完成

**算法流程**：
1. 初始化 `dp[0] = 0`，其余 `dp[i] = n + 1`（一个足够大的值，因为最大答案就是 n）
2. 遍历 `i` 从 1 到 n
3. 对于每个 `i`，遍历所有满足 `i - j * j >= 0` 的完全平方数
4. 状态转移：`dp[i] = min(dp[i], dp[i - j*j] + 1)`
5. 返回 `dp[n]`

## 复杂度
- 时间复杂度：$O(n\sqrt{n})$，外层 n，内层 $\sqrt{n}$（完全平方数的数量）
- 空间复杂度：O(n)，dp 数组

## Code
```cpp
class Solution {
public:
    int numSquares(int n) {
        // 最大答案就是 n（全用 1 组成），用 n+1 避免溢出
        vector<int> dp(n + 1, n + 1);
        dp[0] = 0;  // base case：和为 0 需要 0 个完全平方数

        for (int i = 1; i <= n; i++) {
            // j 从 1 开始：0 不是完全平方数，j=0 无意义
            for (int j = 1; j * j <= i; j++) {
                dp[i] = min(dp[i], dp[i - j * j] + 1);
            }
        }

        return dp[n];
    }
};
```

**问题/优化方向**：
- 初始代码有冗余：预填充所有完全平方数为 1 是不必要的，状态转移本身已经包含这种情况
- 通过循环条件 `j*j <= i` 自然避免数组越界，不需要额外判断

# 思路二：BFS（数学优化视角）

## 解题思路

**核心思想**：将问题转化为图的最短路径问题。

从 0 开始，每次可以加上一个完全平方数，求到达 n 的最少步数。这就是典型的 BFS 求最短路径。

**与 DP 的关系**：
- DP 和 BFS 本质都是在 DAG 上求最短路径
- DP 是"填表"视角，BFS 是"搜索"视角
- 对于这题，DP 更直接，但 BFS 在处理"答案很小"的场景可能更快

## 复杂度
- 时间复杂度：最坏 O(n√n)，与 DP 相同
- 空间复杂度：O(n)，visited 数组 + 队列

## Code
```cpp
class Solution {
public:
    int numSquares(int n) {
        queue<pair<int, int>> q;  // {当前值, 步数}
        vector<bool> visited(n + 1, false);

        q.push({0, 0});
        visited[0] = true;

        while (!q.empty()) {
            auto [val, steps] = q.front();
            q.pop();

            // 尝试所有完全平方数
            for (int i = 1; i * i + val <= n; i++) {
                int next = val + i * i;
                if (next == n) return steps + 1;
                if (!visited[next]) {
                    visited[next] = true;
                    q.push({next, steps + 1});
                }
            }
        }

        return -1;
    }
};
```

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 动态规划 |$ O(n\sqrt{n})$ | $O(n)$ | 直观易懂，面试首选 |
| BFS | $O(n\sqrt{n})$ | $O(n)$ | 图的视角，适合答案小的场景 |
| 数学定理 | $O(\sqrt{n})$ | $O(1)$ | 理论最优，但实现复杂 |

# 关键词与核心洞察

## 关键词
- **动态规划（DP）**：不是背模板，而是理解"子问题结构"。这题的子问题非常清晰：和为 i 的问题依赖于和为更小值的问题
- **DAG 拓扑排序**：Bottom Up DP 的本质是在 DAG 上按拓扑序填表。确定状态之间的依赖关系，就能确定遍历顺序
- **状态转移设计**：`dp[i] = min(dp[i - square] + 1)`，"+1"表示使用了一个完全平方数
- **边界条件处理**：通过循环条件 `j*j <= i` 自然避免负数访问，不需要额外的 if 判断（好代码没有特殊情况）

## Insight

**DP 的本质不是记忆化，而是"从小问题递推到大问题"**

- 很多教程把 DP 讲成"记忆化搜索的优化"，但这只是实现技巧
- 真正的理解是：找到问题的子结构，确定状态之间的依赖关系（DAG），按拓扑序求解
- 当你能从 DAG 的视角看 DP，循环顺序就不再是"背的"，而是"推导的"

**"好品味"的代码细节**
- 初始化值选择 `n+1` 而不是 `INT_MAX`：避免溢出，且语义清晰（最大答案就是 n）
- `j` 从 1 开始而不是 0：`j=0` 意味着用 0 作为完全平方数，这在数学上无意义
- 消除冗余初始化：相信你的状态转移，它能处理所有情况，包括完全平方数本身

**类比与迁移**
- 这道题和「零钱兑换」在 DAG **结构上几乎相同**。
- 区别：279 的"硬币"是固定的（1, 4, 9, 16...），322 的"硬币"是输入给定的
- 这种结构属于"完全背包"问题：物品无限，求最小/最大/方案数

## 易错点
- **循环范围**：内层循环 `j` 应该从 1 开始，不是 0
- **初始化值**：如果用 `INT_MAX`，`+1` 会溢出，需要用 `INT_MAX / 2` 或直接用 `n+1`
- **base case**：`dp[0] = 0` 是唯一的初始化，不需要预填充完全平方数
