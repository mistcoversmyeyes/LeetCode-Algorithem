# 322. 零钱兑换

## 题目描述

给你一个整数数组 `coins` ，表示不同面额的硬币；以及一个整数 `amount` ，表示总金额。

计算并返回可以凑成总金额所需的 **最少的硬币个数** 。如果没有任何一种硬币组合能组成总金额，返回 `-1` 。

你可以认为每种硬币的数量是无限的。

**示例 1：**
```
输入：coins = [1,2,5], amount = 11
输出：3
解释：11 = 5 + 5 + 1
```

**示例 2：**
```
输入：coins = [2], amount = 3
输出：-1
```

---

# 思路一：动态规划（✅ 最终解法）

## 解题思路

**核心思想**：`dp[i]` 表示凑成金额 `i` 所需的最少硬币个数。

状态转移方程：
```
dp[i] = min(dp[i - coin] + 1)  for all coin in coins where coin <= i
```

**算法流程**：
1. 初始化 `dp` 数组，大小为 `amount + 1`，初始值为 `amount + 1`（表示"无穷大"）
2. `dp[0] = 0`（凑成金额 0 需要 0 个硬币）
3. 外层循环遍历金额 `i` 从 1 到 `amount`
4. 内层循环遍历所有硬币，若 `coin <= i`，更新 `dp[i]`
5. 返回 `dp[amount]`，若大于 `amount` 则返回 -1

## 复杂度
- 时间复杂度：$O(\mathtt{amount} × n)$，$n$ 为硬币种类数
- 空间复杂度：$O(\mathtt{amount})$

## Code
```cpp
#include <vector>
#include <algorithm>

using namespace std;

class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        vector<int> dp(amount + 1, amount + 1);
        sort(coins.begin(), coins.end());  // 排序，配合内层循环终止条件

        // base case：凑成金额 0 需要 0 个硬币
        dp[0] = 0;

        for (int i = 1; i < amount + 1; i++) {
            // 遍历所有小于等于 i 的硬币
            for (int j = 0; j < coins.size() && i - coins[j] >= 0; j++) {
                dp[i] = min(dp[i - coins[j]] + 1, dp[i]);
            }
        }

        return dp[amount] > amount ? -1 : dp[amount];
    }
};
```

# 思路二：初始实现（❌ 有 Bug）

## 解题思路

最初我的内层循环条件顺序写错了：
```cpp
// 错误的顺序！
for (int j = 0; i - coins[j] >= 0 && j < coins.size(); j++)
```

**问题分析**：
- 当 `coins = [474, 83, 404, 3]`（无序）时
- i = 264，j = 0，`coins[0] = 474`
- `264 - 474 >= 0` 为 false，条件短路，循环直接退出
- **硬币 83 和 3 根本没被考虑到！**

**修复过程**：
1. 先交换条件顺序为 `j < coins.size() && i - coins[j] >= 0`
2. 但后来发现，如果硬币数组无序，仍然会提前遇到大面额硬币
3. 最终方案：先 `sort(coins)`，再配合正确的条件顺序

**关键洞察**：
```
// 错误：可能导致数组越界（先访问 coins[j] 再检查 j）
i - coins[j] >= 0 && j < coins.size()

// 正确：先检查下标合法性
j < coins.size() && i - coins[j] >= 0
```

# 思路三：如何记录具体路径（Follow-up）

## 解题思路

**问题**：如果要求输出具体用了哪些硬币，怎么改？

**错误设计**：`dp[i] = pair<vector<int>, int>`
- 每个状态存一个 vector，空间复杂度 O(amount²)
- 会 MLE（内存超限）

**正确设计**：
```cpp
vector<int> dp(amount + 1, amount + 1);      // 最少硬币数
vector<int> from(amount + 1, -1);            // 从哪个金额转移过来
```

**路径还原**：
若 `from[6] = 4`，`from[4] = 2`，`from[2] = 0`：
- 路径：6 → 4 → 2 → 0
- 用的硬币：6-4=2，4-2=2，2-0=2
- 即 [2, 2, 2]

空间复杂度：O(amount)

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 动态规划 | O(amount × n) | O(amount) | ✅ 最优解法，自底向上填表 |
| 带路径记录的 DP | O(amount × n) | O(amount) | 额外数组记录路径 |
| 错误实现 | - | - | ❌ 条件顺序错误导致漏解 |

---

# 关键 Insight

1. **初始值的选择**：用 `amount + 1` 作为"无穷大"，因为最多用 `amount` 个 1 元硬币就能凑出任何金额

2. **条件顺序的陷阱**：`&&` 是短路运算符，访问数组前先检查下标合法性

3. **排序的作用**：不仅为了配合终止条件，也让内层循环能提前退出（一旦硬币 > i 就停止）

4. **路径记录**：不要为了"方便"存 vector，用"从哪来"即可还原路径
