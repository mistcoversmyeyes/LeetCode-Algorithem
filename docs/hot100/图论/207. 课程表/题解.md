**207.** 课程表 - 题解
====

# 题目描述

你需要选修 `numCourses` 门课程，标记为 `0` 到 `numCourses - 1`。某些课程需要先修其他课程。先修关系通过数组 `prerequisites` 表示，其中 `prerequisites[i] = [a, b]` 表示要学习课程 `a` 必须先完成课程 `b`。

请判断是否能完成所有课程。

**示例 1：**
- 输入：`numCourses = 2, prerequisites = [[1,0]]`
- 输出：`true`

**示例 2：**
- 输入：`numCourses = 2, prerequisites = [[1,0],[0,1]]`
- 输出：`false`

**约束条件：**
- `1 <= numCourses <= 2000`
- `0 <= prerequisites.length <= 5000`

# 思路一：邻接矩阵 + BFS 拓扑排序

## 解题思路

**核心思想**：这道题本质上是检测有向图中是否有环——如果课程依赖关系构成了环，就不可能完成所有课程。用拓扑排序（Kahn 算法）来检测。

我一上来就识别出这是拓扑排序问题。但立刻遇到一个问题：题目给的图是以**边集**（Edge List）的形式表示的，不能直接用于拓扑排序算法。

**图表示的选择过程**：

我最初想到用**邻接矩阵**来存图。numCourses 最大 2000，邻接矩阵 2000×2000 = 4×10⁶，空间上勉强可以接受。

**拓扑排序的思路**：
1. 扫描 `prerequisites`，构建邻接矩阵，同时用一个一维数组记录每个节点的入度（避免每次从邻接矩阵算列和，那要 O(V²)）
2. 找到所有入度为 0 的节点，放入队列
3. 每次从队列取出一个节点，遍历它的邻居，将邻居入度减 1
4. 如果邻居入度变为 0，入队
5. 最后检查是否所有节点入度都归零

**关键发现：邻接表不需要更新**

在思考过程中我一度纠结：删除一个节点后，是否需要更新邻接矩阵/邻接表？后来想通了——拓扑排序中"删除节点"只需要更新**入度数组**，邻接表/矩阵始终是只读的查询工具，用来回答"u 的邻居有哪些"。

**遇到的 Bug**：

第一版代码里，遍历邻居时把"减入度"和"判断是否入队"的逻辑耦合错了——对所有节点（不仅是邻居）都判断入度是否为 0，导致非邻居节点也被错误入队。修复方法是只在入度**真正被减少**之后才判断是否入队。

## 复杂度
- 时间复杂度：O(V² + E)，每次删节点需要 O(V) 扫描邻接矩阵的一行找邻居，共 V 个节点
- 空间复杂度：O(V²)，邻接矩阵

## Code
```cpp
class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        // 邻接矩阵建图
        auto adj_matrix = vector<vector<int>>(numCourses, vector<int>(numCourses, 0));
        for (auto& prereq : prerequisites) {
            adj_matrix[prereq.back()][prereq.front()]++;
        }

        // 统计入度
        auto in_degree = vector<int>(numCourses, 0);
        for (auto& prereq : prerequisites) {
            in_degree[prereq.front()]++;
        }

        // 入度为 0 的节点入队
        auto qu = queue<int>();
        for (int i = 0; i < numCourses; i++) {
            if (in_degree[i] == 0) {
                qu.push(i);
            }
        }

        // BFS 拓扑排序
        while (!qu.empty()) {
            int node = qu.front();
            qu.pop();
            for (int j = 0; j < numCourses; j++) {
                if (adj_matrix[node][j] > 0) {
                    in_degree[j]--;
                    if (in_degree[j] == 0) {
                        qu.push(j);
                    }
                }
            }
        }

        // 检查是否所有课程都完成
        for (auto& degree : in_degree) {
            if (degree != 0) return false;
        }
        return true;
    }
};
```

**问题/优化方向**：
- 邻接矩阵每次找邻居要 O(V) 扫描整行，对稀疏图来说浪费严重
- 空间 O(V²) 也不理想

# 思路二：邻接表 + BFS 拓扑排序（✅ 推荐解法）

## 解题思路

**核心思想**：把邻接矩阵换成邻接表，找邻居的代价从 O(V) 降到 O(出度)。

在面试官引导下分析了邻接矩阵的瓶颈——每次删节点找邻居都是 O(V) 扫描，而邻接表只访问真正有边的邻居。整体时间复杂度从 O(V²) 优化到 O(V + E)。

算法流程和思路一完全一致，只是图的存储方式换了。

**算法流程**：
1. 遍历 `prerequisites`，构建邻接表 + 统计入度
2. 所有入度为 0 的节点入队
3. BFS：取出节点，遍历邻居，减入度，入度归零则入队
4. 最终检查是否所有节点入度为 0

## 复杂度
- 时间复杂度：O(V + E)，每个节点和每条边各被访问一次
- 空间复杂度：O(V + E)，邻接表

## Code
```cpp
class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        // 邻接表建图
        auto adj_list = vector<vector<int>>(numCourses);
        auto in_degree = vector<int>(numCourses, 0);
        for (auto& prereq : prerequisites) {
            adj_list[prereq.back()].push_back(prereq.front());
            in_degree[prereq.front()]++;
        }

        // 入度为 0 的节点入队
        auto qu = queue<int>();
        for (int i = 0; i < numCourses; i++) {
            if (in_degree[i] == 0) {
                qu.push(i);
            }
        }

        // BFS 拓扑排序
        while (!qu.empty()) {
            int node = qu.front();
            qu.pop();
            for (auto& adj_node : adj_list[node]) {
                in_degree[adj_node]--;
                if (in_degree[adj_node] == 0) {
                    qu.push(adj_node);
                }
            }
        }

        // 检查是否所有课程都完成
        for (auto& degree : in_degree) {
            if (degree != 0) return false;
        }
        return true;
    }
};
```

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 邻接矩阵 + BFS | O(V² + E) | O(V²) | 实现直观，但对稀疏图浪费 |
| 邻接表 + BFS | O(V + E) | O(V + E) | 最优解，稀疏图友好 |

# 关键词与核心洞察

## 关键词
- **拓扑排序（Kahn 算法）**：BFS 版本的拓扑排序，用队列维护入度为 0 的节点，每次"删除"一个节点就是将其邻居入度减 1
- **图的表示转换**：题目给的是边集（Edge List），需要转换为邻接表才能高效操作。选择图的表示方式要根据实际操作需求——本题核心操作是"遍历一个节点的所有邻居"，邻接表最合适
- **环检测**：拓扑排序能完成（所有节点入度归零）等价于图无环。有环的节点入度永远不会变为 0

## Insight
- **拓扑排序中"删除节点"是逻辑删除**：不需要修改图结构（邻接表/矩阵），只需要修改入度数组。邻接表始终是只读的查询工具。这个认知很关键——一开始我纠结"删除节点后怎么更新邻接表"，想通这一点后代码就清晰了
- **用队列收集入度为 0 的节点**：避免每轮 O(V) 扫描入度数组。当邻居入度减到 0 时**立刻入队**，而不是之后再去找

## 易错点
- 遍历邻居时，入队判断必须放在"入度真正被减少"之后的 if 里，不能对所有节点做入度为 0 的判断，否则会把本来入度就是 0 的非邻居节点错误入队
- `prerequisites[i] = [a, b]` 表示 b → a 的有向边（先修 b 才能学 a），建图方向不要搞反

---

**推荐**：面试中使用**思路二（邻接表 + BFS）**，时间空间都是最优的 O(V + E)，代码简洁清晰。
