# 215. 数组中的第K个最大元素 - 题解

**题目链接**: https://leetcode.cn/problems/kth-largest-element-in-an-array/

**标签**: 数组、分治、快速选择、排序、堆

---

# 题目描述

给定整数数组 `nums` 和整数 `k`，请返回数组中第 `k` 个最大的元素。

请注意，你需要找的是数组排序后的第 `k` 个最大的元素，而不是第 `k` 个不同的元素。

**示例 1:**
```
输入: [3,2,1,5,6,4] 和 k = 2
输出: 5
```

**示例 2:**
```
输入: [3,2,3,1,2,4,5,5,6] 和 k = 4
输出: 4
```

---

# 思路一：小根堆（✅ 面试推荐）

## 解题思路

**核心思想**：维护一个大小为 k 的小根堆，堆顶即为第 k 大的元素。

遍历数组，如果堆未满直接加入；如果堆已满且当前元素大于堆顶，则弹出堆顶、加入当前元素。最终堆顶就是答案。

**算法流程**：
1. 初始化大小为 k 的小根堆
2. 遍历数组每个元素：
   - 堆大小 < k：直接 push
   - 堆大小 == k 且 num > 堆顶：pop 堆顶，push num
3. 返回堆顶元素

## 复杂度

- **时间复杂度**：O(n log k)
  - 每个元素最多一次堆操作（push/pop 都是 O(log k)）
- **空间复杂度**：O(k)
  - 堆的大小始终为 k

## Code

```cpp
class Solution {
public:
    int findKthLargest(vector<int>& nums, int k) {
        // 小根堆，C++ 默认是大根堆，需要指定 greater<int>
        priority_queue<int, vector<int>, greater<int>> min_heap;

        for (int num : nums) {
            min_heap.push(num);
            // 保持堆的大小为 k，超出则弹出最小元素
            if (min_heap.size() > k) {
                min_heap.pop();
            }
        }

        return min_heap.top();  // 堆顶就是第 k 大的元素
    }
};
```

**问题/优化方向**：
- 空间复杂度 O(k)，适合 k 较小的情况
- 如果 k 接近 n，可以改为维护大根堆找第 n-k 小的元素

# 思路二：Hoare 快速选择

## 解题思路

**核心思想**：利用快速排序的 partition 思想，每次将数组分为两部分，通过比较目标位置与分界点，只递归处理包含答案的那一半。

将问题转化为"找第 n-k 小的元素"（0-based）。使用 Hoare partition 将数组分为 `[left, j]`（全 `<= pivot`）和 `[j+1, right]`（全 `>= pivot`）两部分，根据目标位置 `k` 与 `j` 的关系决定递归方向。

**算法流程**：
1. 选择 pivot（首元素）
2. 使用双指针从两端向中间扫描，将小于 pivot 的放左边，大于 pivot 的放右边
3. 得到分界点 `j`
4. 如果 `k <= j`，答案在左半部分，递归 `[left, j]`
5. 如果 `k > j`，答案在右半部分，递归 `[j+1, right]`

## 复杂度

- **时间复杂度**：平均 O(n)，最坏 O(n²)
  - 每次 partition 遍历当前区间，期望将问题规模减半
  - 最坏情况（已排序数组且每次都选边界）：O(n²)
- **空间复杂度**：O(log n) 递归栈空间

## Code

```cpp
class Solution {
public:
    int partition(vector<int>& nums, int left, int right) {
        int pivot = nums[left];
        int i = left - 1, j = right + 1;

        while (i < j) {
            do ++i; while (nums[i] < pivot);
            do --j; while (nums[j] > pivot);
            if (i < j) swap(nums[i], nums[j]);
        }
        return j;  // 返回分界点，不是 pivot 的最终位置
    }

    int quick_selection(vector<int>& nums, int left, int right, int k) {
        if (left == right) return nums[left];

        int split_idx = partition(nums, left, right);
        // 左边 [left, split_idx] 全 <= pivot
        // 右边 [split_idx+1, right] 全 >= pivot

        if (k <= split_idx)
            return quick_selection(nums, left, split_idx, k);
        else
            return quick_selection(nums, split_idx + 1, right, k);
    }

    int findKthLargest(vector<int>& nums, int k) {
        // 第 k 大 = 第 n-k 小（0-based）
        return quick_selection(nums, 0, nums.size() - 1, nums.size() - k);
    }
};
```

**问题/优化方向**：
- Hoare partition 的 `j` 只是分界点，不是 pivot 的最终位置，不能 `k == j` 时直接返回
- 最坏情况时间复杂度退化到 O(n²)，可通过随机选 pivot 优化

# 思路三：Lomuto 快速选择

## 解题思路

**核心思想**：使用 Lomuto partition（单指针版本），pivot 固定在数组末尾，partition 后 pivot 的位置就是它的最终排名位置。

相比 Hoare，Lomuto 的循环不变量更直观：维护 `[left, i]` 为 `<= pivot` 的区域，`[i+1, j-1]` 为 `> pivot` 的区域。

**算法流程**：
1. 选择 pivot（末尾元素）
2. 单指针 `i` 从左向右扫描，遇到 `<= pivot` 的元素就交换到 `i` 位置
3. 最后将 pivot 放到 `i+1` 位置，返回 `i+1` 作为 pivot 最终位置
4. 如果 `k == p`，找到答案；否则递归左半或右半部分

## 复杂度

- **时间复杂度**：平均 O(n)，最坏 O(n²)
- **空间复杂度**：O(log n) 递归栈空间

## Code

```cpp
class Solution {
public:
    int partition(vector<int>& nums, int left, int right) {
        int pivot = nums[right];  // 选择末尾元素作为 pivot
        int i = left - 1;

        for (int j = left; j < right; j++) {
            if (nums[j] <= pivot) {
                swap(nums[++i], nums[j]);
            }
        }
        swap(nums[++i], nums[right]);  // pivot 放到正确位置
        return i;  // 返回 pivot 的最终位置
    }

    int quick_selection(vector<int>& nums, int left, int right, int k) {
        if (left == right) return nums[left];

        int p = partition(nums, left, right);

        if (k == p) return nums[p];        // 命中！
        else if (k < p)
            return quick_selection(nums, left, p - 1, k);  // 去左边
        else
            return quick_selection(nums, p + 1, right, k); // 去右边
    }

    int findKthLargest(vector<int>& nums, int k) {
        return quick_selection(nums, 0, nums.size() - 1, nums.size() - k);
    }
};
```

**问题/优化方向**：
- 在重复元素多的情况下（如 `[1,1,1,1,1...]`），Lomuto 会严重退化到 O(n²)
  - 原因：`<= pivot` 将所有相等的元素都分到左边，分区极度不平衡
- 相比 Hoare，Lomuto 对重复元素的处理能力较弱

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 小根堆 | O(n log k) | O(k) | 代码简洁，性能稳定，面试推荐 |
| Hoare 快速选择 | 平均 O(n)，最坏 O(n²) | O(log n) | 交换次数少，对重复元素处理较好 |
| Lomuto 快速选择 | 平均 O(n)，最坏 O(n²) | O(log n) | 实现直观，但重复元素会退化 |

# 关键词与核心洞察

## 关键词

- **小根堆**：维护大小为 k 的堆，堆顶即为第 k 大元素。C++ 中使用 `priority_queue<int, vector<int>, greater<int>>`。
- **快速选择（Quick Select）**：基于 partition 的选择算法，平均 O(n) 时间找第 k 小/大元素。核心思想是"只处理包含答案的那一半"。
- **Hoare vs Lomuto partition**：Hoare 用双指针从两端对撞，返回分界点（pivot 位置不确定）；Lomuto 用单指针从左向右，返回 pivot 最终位置。
- **循环不变量**：算法正确性的核心。Hoare 维护 `[left,i) <= pivot` 和 `(j,right] >= pivot`；Lomuto 维护 `[left,i] <= pivot` 和 `[i+1,j) > pivot`。
- **三路 partition**：处理重复元素的优化，将数组分为 `< pivot`、`== pivot`、`> pivot` 三部分，避免退化。

## Insight

- **面试策略的选择**：小根堆代码最简洁（5-6 行），不易出错，是面试中的安全选择；快速选择平均时间最优但实现复杂，适合展示算法功底。
- **快速选择的本质**：不是排序，而是"逐步缩小搜索范围"。每次 partition 后，我们能确定答案在哪一半，另一半可以直接丢弃。
- **Hoare partition 的陷阱**：返回的 `j` 不是 pivot 的最终排名，只是分界点。因此快速选择中 `k == j` 时不能直接返回，必须继续递归到区间长度为 1。
- **partition 的鲁棒性**：当数组有大量重复元素时，Lomuto 的 `<=` 会将所有相等元素分到一边导致退化；Hoare 的 `<` 和 `>` 让相等元素分散到两边，分区更平衡。
- **时空权衡**：快速选择平均时间最优（O(n)）但有 O(n²) 风险；堆解法时间稳定（O(n log k)）且代码简单，是面试中的安全选择。

## 易错点

- **小根堆的 C++ 语法**：需要 `priority_queue<int, vector<int>, greater<int>>`，注意 `greater<int>` 是类型，如果要用 lambda 需要 `decltype(cmp)` 并传给构造函数。
- **空堆访问**：使用 `top()` 前必须确保堆非空，否则运行时错误。
- **Hoare partition 最后不要 swap pivot**：标准 Hoare 不需要 `swap(nums[left], nums[j])`，返回的 `j` 只是分界点。
- **快速选择的递归区间**：Hoare 是 `k <= j` 去 `[left, j]`，`k > j` 去 `[j+1, right]`；Lomuto 是 `k == p` 命中，`k < p` 去 `[left, p-1]`，`k > p` 去 `[p+1, right]`。

---

**推荐**：面试中使用**小根堆**或**Hoare 快速选择（随机 pivot）**，前者代码简洁不出错，后者时间复杂度最优。如果面试官追问优化，可以讨论三路 partition 处理重复元素的情况。
