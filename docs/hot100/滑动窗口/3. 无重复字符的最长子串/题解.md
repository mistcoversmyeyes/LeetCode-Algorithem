**3.** 无重复字符的最长子串 - 题解
====

# 题目描述

给定一个字符串 `s` ，请你找出其中不含有重复字符的 **最长子串** 的长度。

**示例 1：**
```
输入: s = "abcabcbb"
输出: 3
解释: 因为无重复字符的最长子串是 "abc"，所以其长度为 3。
```

**示例 2：**
```
输入: s = "bbbbb"
输出: 1
解释: 因为无重复字符的最长子串是 "b"，所以其长度为 1。
```

**示例 3：**
```
输入: s = "pwwkew"
输出: 3
解释: 因为无重复字符的最长子串是 "wke"，所以其长度为 3。
     请注意，你的答案必须是 子串 的长度，"pwke" 是一个子序列，不是子串。
```

---

# 导读

## 关键词
- **滑动窗口（双指针法）**：不只是"避免临时数组的额外空间"，更深层次的原因是"能够快速跳过不可能的子数组"。一旦检测到重复字符，包含这两个重复字符的子串都不合法，可以剪枝。
- **剪枝思想**：暴力法的问题是盲目搜索所有可能的子串。滑动窗口通过"一旦确定某个条件就不可能更优"来剪枝，将搜索空间从 O(n²) 降到 O(n)。
- **哈希表更新时机**：遇到重复字符时，不仅要移动左指针，还要更新哈希表中该字符的位置。这个细节很容易出错，顺序错了就会导致后续判断错误。

## Insight
**双指针法的本质理解**：
- 表层理解：用两个指针代替临时数组，省空间
- **深层理解**：左指针收缩排除"不可能的解"，右指针扩展寻找"更优的解"。一旦发现重复字符，所有包含这两个重复字符的子串都不合法，立即跳过。这才是双指针法的核心价值——剪枝，而不是省空间。

**滑动窗口的剪枝逻辑**：
- 暴力法：检查每个子串，即使包含重复字符也继续检查
- 滑动窗口：遇到重复字符，立即移动左指针跳到重复字符的下一个位置，中间的所有子串都不检查了
- 这就是为什么每个字符最多被访问两次（一次进窗口，一次出窗口），时间复杂度从 O(n²) 降到 O(n)

## 易错点
- **更新顺序错误**：在第 41 行（更新 `left_index`）之后，必须添加 `appear[s[right_index]] = right_index;` 来更新重复字符的位置。如果先更新位置再计算 `left_index`，会导致左指针移动错误。
- **边界情况遗漏**：循环结束后要再检查一次当前窗口长度。例如 `"abc"`，循环结束后 `left_index=0, right_index=3`，需要计算 `3-0=3` 作为最终答案。
- **删除范围错误**：遇到重复字符时，要删除的是"左指针到重复字符旧位置之间的所有记录"，不是"左指针到右指针之间的所有记录"。

# 思路一：暴力法

## 解题思路

**核心思想**：枚举所有可能的子串，检查每个子串是否有重复字符，记录最长长度。

这是我最自然的想法：对于每个起始位置，向后扩展，直到遇到重复字符。

**算法流程**：
1. 外层循环遍历每个起始位置 `i`
2. 内层循环从 `i` 开始向后遍历，用哈希集合检查字符是否重复
3. 遇到重复字符时，记录当前子串长度
4. 更新全局最大长度

## 复杂度
- 时间复杂度：O(n²) —— 两层嵌套循环，每次检查重复需要 O(1)
- 空间复杂度：O(min(m, n)) —— 哈希集合的大小，m 是字符集大小

## Code
```cpp
class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        int n = s.length();
        int max_length = 0;

        for (int i = 0; i < n; i++) {
            unordered_set<char> seen;
            int j = i;
            while (j < n && seen.find(s[j]) == seen.end()) {
                seen.insert(s[j]);
                j++;
            }
            max_length = max(max_length, j - i);
        }

        return max_length;
    }
};
```

**问题/优化方向**：
存在大量多余的计算。暴力法的问题在于：一旦检测到重复字符，我们就可以确定**以当前起始位置开头、包含这两个重复字符的子串都不可能更长了**，可以立即停止向右扩展。

例如对于 `"abcabc"`：
- 以位置 0 开头，检查到 `"abc"` 都是合法的
- 继续向右，遇到重复的 `'a'`，此时包含两个 `'a'` 的子串 `"abca"` 已经不合法
- **关键启发**：以位置 0 开头的所有更长子串（`"abcab"`、`"abcabc"` 等）都必然包含这两个重复的 `'a'`，都不可能是答案
- 因此可以**剪枝**：跳过这些不可能的子串，直接移动起始位置

这就是**滑动窗口（双指针法）** 的优化思想：每个字符最多被访问两次（一次被右指针扩展，一次被左指针收缩），将时间复杂度从 O(n²) 优化到 O(n)。

# 思路二：滑动窗口 + 哈希表（❌ 第一次实现有 Bug）

## 解题思路

**核心思想**：使用滑动窗口，左右两个指针表示当前无重复子串的范围，用哈希表记录字符出现的位置。

我想到可以用双指针优化：右指针向右扩展，遇到重复字符时，左指针跳到重复字符的下一个位置。这样每个字符最多被访问两次。

**算法流程**：
1. 初始化 `left_index = 0, right_index = 0`
2. 右指针向右遍历，用哈希表记录字符位置
3. 如果遇到重复字符，更新最大长度，然后将左指针跳到重复字符的下一个位置
4. 删除左指针移动过程中经过的字符

## Code
```cpp
// ❌ 有 Bug 的初版代码
class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        int left_index = 0;
        int right_index = 0;
        unordered_map<char, int> appear;
        int max_length = 1;

        while (right_index < s.length()) {
            if (appear.find(s[right_index]) == appear.end()) {
                appear.insert(make_pair(s[right_index], right_index));
            }
            else {
                // 更新最长字串长度
                int cur_length = right_index - left_index;
                if (cur_length > max_length) {
                    max_length = cur_length;
                }

                // 跳过中间不可能的字串
                for (int i = left_index; i < appear.find(s[right_index])->second; i++) {
                    appear.erase(s[i]);
                }
                left_index = appear.find(s[right_index])->second + 1;
                // ❌ Bug：这里没有更新重复字符的位置！
            }

            right_index = right_index + 1;
        }
        return max_length;
    }
};
```

**问题/优化方向**：
- 测试用例 `"abcabcbb"` 输出 5，期望 3
- 测试用例 `"pwwkew"` 输出 2，期望 3

**关键 Bug**：
在更新 `left_index` 后，没有更新哈希表中重复字符的位置。导致下次遇到该字符时，获取到的是旧位置，计算错误。

# 思路三：滑动窗口 + 哈希表（✅ 修复后通过）

## 解题思路

**核心思想**：在面试官的引导下，发现了更新顺序的问题。修复后，每次移动左指针时，必须同步更新哈希表中重复字符的位置。

这是在面试官引导下发现的方法：
- 面试官问："当遇到重复字符时，`appear` 里存的是什么？"
- 我答："字符到它上次出现位置的映射"
- 面试官问："当你移动 `left_index` 后，`appear` 里那个重复字符的位置还是对的吗？"
- 我恍然大悟："哦！我忘记更新重复字符的位置了！"

**关键修复**：
在第 41 行（更新 `left_index`）之后，必须添加 `appear[s[right_index]] = right_index;` 来更新重复字符的位置。

**算法流程**：
1. 初始化 `left_index = 0, right_index = 0`，哈希表 `appear` 记录字符位置
2. 右指针向右遍历：
   - 如果字符未出现过，记录位置
   - 如果字符已出现：
     a. 更新最大长度
     b. 删除左指针到重复字符之间的所有记录
     c. 将左指针移动到重复字符的下一个位置
     d. **更新重复字符的位置为当前位置**（关键修复）
3. 右指针继续右移
4. 循环结束后，再检查一次当前窗口长度（处理最长子串在末尾的情况）

## 复杂度
- 时间复杂度：O(n) —— 左右指针各遍历一次字符串
- 空间复杂度：O(min(m, n)) —— 哈希表存储字符位置，m 是字符集大小

## Code
```cpp
class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        // 处理空字符串边界情况
        if (s.length() == 0) {
            return 0;
        }

        int left_index = 0;
        int right_index = 0;
        unordered_map<char, int> appear;  // 记录字符最后一次出现的位置
        int max_length = 1;

        while (right_index < s.length()) {
            // 当前字符未出现过，直接记录位置
            if (appear.find(s[right_index]) == appear.end()) {
                appear.insert(make_pair(s[right_index], right_index));
            }
            else {
                // 遇到重复字符，先更新最长子串长度
                int cur_length = right_index - left_index;
                if (cur_length > max_length) {
                    max_length = cur_length;
                }

                // 删除左指针到重复字符位置之间的所有字符记录
                // 这些字符都在窗口外了，不再影响后续判断
                for (int i = left_index; i < appear.find(s[right_index])->second; i++) {
                    appear.erase(s[i]);
                }

                // 将左指针移动到重复字符的下一个位置
                left_index = appear.find(s[right_index])->second + 1;

                // ✅ 关键修复：更新重复字符的位置为当前位置
                appear[s[right_index]] = right_index;
            }

            right_index = right_index + 1;
        }

        // 循环结束后，检查最后一个窗口的长度
        // 防止最长子串在字符串末尾的情况被遗漏
        int cur_length = right_index - left_index;
        if (cur_length > max_length) {
            max_length = cur_length;
        }

        return max_length;
    }
};
```

**边界情况处理**：
1. **空字符串**：返回 0
2. **最长子串在末尾**：循环结束后再检查一次当前窗口长度
3. **所有字符都不同**：右指针一直右移，最后一次性计算长度
4. **所有字符都相同**：每次遇到重复都更新，最终返回 1

# 思路四：滑动窗口 + 合法窗口不变量（✅ 当前推荐模板）

## 解题思路

**核心思想**：把滑动窗口写成“先用当前合法窗口更新答案 -> 再构造下一个合法窗口”的两步走结构。整个逻辑是 "初始化合法窗口 -> 循环开始时窗口一定合法 -> 使用当前合法窗口更新答案 -> 获取下一个合法窗口"。

这次真正想清楚的点，不再是“右指针加一个字符后再抢救式修窗口”，而是：

- 每次进入循环时，`[left, right]` 已经是一个**合法窗口**
- 因为当前窗口合法，所以这一步可以直接用来更新答案
- 更新完答案之后，再去想“如何得到下一个合法窗口”
- 获取下一个合法窗口时，只需要盯着 `s[right + 1]` 这个即将加入的新字符

这样写的好处是表达非常清楚。面试里讲的时候，可以直接围绕循环不变量来展开，而不是把“扩右边界”和“修重复字符”搅在一起。

**算法流程**：
1. 初始化一个最小合法窗口：`left = right = 0`，窗口里只有 `s[0]`
2. 循环开始时保证 `[left, right]` 内字符互不重复
3. 先用当前合法窗口长度 `cur_len` 更新答案
4. 如果没有下一个字符了，直接结束
5. 否则令 `next_char = s[right + 1]`
6. 如果 `next_char` 已经在窗口中，就不断右移 `left` 并同步删除窗口左端字符，直到 `next_char` 可以安全加入
7. 最后再把 `right` 右移一位，将 `next_char` 加入窗口，进入下一轮

## 复杂度
- 时间复杂度：O(n) —— 每个字符最多进窗口一次、出窗口一次
- 空间复杂度：O(1) —— 这里用定长数组记录 ASCII 字符是否在窗口中，数组大小为 128

## Code
```cpp
class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        if (s.empty()) {
            return 0;
        }

        int ans = 1;
        int left = 0;
        int right = 0;
        int cur_len = 1;
        vector<bool> appear_in_window(128, false);
        appear_in_window[s[0]] = true;

        // 循环开始时，[left, right] 始终是一个合法窗口。
        while (right < s.size()) {
            // Step 1: 当前窗口合法，可以直接更新答案。
            auto to_update = [&]() {
                return cur_len > ans;
            };
            if (to_update()) {
                ans = cur_len;
            }

            // Step 2: 获取下一个合法窗口。
            // 先判断是否没有下个窗口了?
            if (right + 1 == s.size()) {
                break;
            }

            // 通过收缩左边界跳过哪些不可能的字串起点 left
            char next_char = s[right + 1];
            while (appear_in_window[next_char]) {
                appear_in_window[s[left]] = false;
                left++;
                cur_len--;
            }

            // 真正移动窗口
            right++;
            appear_in_window[next_char] = true;
            cur_len++;
        }

        return ans;
    }
};
```

**问题/优化方向**：
- 这版代码的优势不在于比标准答案更快，而在于**循环不变量特别清晰**，适合面试时讲解
- `cur_len` 被当成显式维护的状态，而不是每次用 `right - left + 1` 现算，更符合“状态机式”思考
- 如果更追求代码短小，可以改成 `lastSeen` 模板；如果更追求讲解清晰，这版更合适

# 这次真正想清楚的点

这次最大的收获，不是又多记住了一种写法，而是把这题的滑动窗口组织方式想顺了：

1. 可以把窗口写成“**循环开始时已经合法**”的形式
2. 既然当前窗口合法，那就应该先更新答案
3. 更新完答案之后，再去考虑怎么得到下一个合法窗口
4. 真正需要处理冲突的，不是当前 `s[right]`，而是下一步准备加入窗口的 `s[right + 1]`
5. `cur_len` 作为显式状态维护时，窗口迁移会更好讲

这一版更适合你在面试里表达，因为它天然就是“当前状态 -> 更新答案 -> 转移到下一个状态”的节奏。

# 关键要点

1. **滑动窗口的核心思想**：左右指针维护一个无重复字符的窗口，右指针扩展，左指针收缩。每个字符最多被访问两次（一次被右指针，一次被左指针）。

2. **哈希表的更新时机**：遇到重复字符时，不仅要移动左指针，还要更新哈希表中该字符的位置。这是最容易出错的地方。

3. **循环不变量写法**：
   - 可以把滑动窗口写成“循环开始时窗口合法”的形式
   - 先更新答案，再获取下一个合法窗口
   - 这种写法在面试里更容易讲清楚

4. **边界情况**：
   - 空字符串需要特殊处理
   - 如果字符集不是 `a-z`，就不能只开 `26`
   - 这里使用 `128` 是因为题目按 ASCII 处理足够

5. **调试技巧**：
   - 使用 `printf` 输出 `left_index` 和 `right_index` 观察窗口变化
   - 测试用例：`"abcabcbb"`（重复字符间隔不同）、`"pwwkew"`（连续重复）、`""`（空串）、`"bbbbbb"`（全相同）

---

**推荐**：面试中优先使用**思路四（合法窗口不变量版）**。复杂度同样是 O(n)，但结构更清楚，更适合在高压场景下稳定表达。前面的哈希表位置版可以作为你理解“为什么会出 bug”的对照材料。
