**33.** 搜索旋转排序数组 - 题解
====

# 题目描述

整数数组 `nums` 按升序排列，数组中的值 **互不相同** 。

在传递给函数之前，`nums` 在预先未知的某个下标 `k`（`0 <= k < nums.length`）上进行了 **向左旋转**，使数组变为 `[nums[k], nums[k+1], ..., nums[n-1], nums[0], nums[1], ..., nums[k-1]]`（下标 **从 0 开始** 计数）。例如， `[0,1,2,4,5,6,7]` 下标 `3` 上向左旋转后可能变为 `[4,5,6,7,0,1,2]` 。

给你 **旋转后** 的数组 `nums` 和一个整数 `target` ，如果 `nums` 中存在这个目标值 `target` ，则返回它的下标，否则返回 `-1` 。

你必须设计一个时间复杂度为 `O(log n)` 的算法解决此问题。

**示例 1：**
```
输入：nums = [4,5,6,7,0,1,2], target = 0
输出：4
```

**示例 2：**
```
输入：nums = [4,5,6,7,0,1,2], target = 3
输出：-1
```

**示例 3：**
```
输入：nums = [1], target = 0
输出：-1
```

---

# 思路一：先找旋转点，再在虚拟升序数组上二分

## 解题思路

**核心思想**：先找到旋转点k，将旋转数组还原为逻辑上的升序数组，然后用普通二分查找。

这是我最自然的想法：旋转数组虽然整体不有序，但它是由两个有序段拼接而成的。如果能找到旋转点，就能把它"还原"成一个从k开始的虚拟升序数组。

**算法流程**：
1. 二分查找旋转点k（nums[k]是数组最小值，左段都比nums[k]大，右段都比nums[k]小）
2. 在虚拟升序数组[0, n)上做普通lower_bound二分
3. 虚拟位置mid映射回原数组：realMid = (mid + k) % n

## 复杂度
- 时间复杂度：O(log n)，两次二分
- 空间复杂度：O(1)

## Code
```cpp
int search(vector<int>& nums, int target) {
    int n = nums.size();
    if (n == 0) return -1;

    // 第一步：找旋转点k（最小值位置）
    int l = 0, r = n - 1;
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] > nums[r]) {
            l = mid + 1;  // 最小值在右半边
        } else {
            r = mid;      // 最小值在左半边（包括mid）
        }
    }
    int k = l;  // 旋转点

    // 第二步：在虚拟升序数组上做lower_bound
    l = 0, r = n;
    while (l < r) {
        int mid = l + (r - l) / 2;
        int realMid = (mid + k) % n;  // 映射回原数组

        if (nums[realMid] >= target) {
            r = mid;
        } else {
            l = mid + 1;
        }
    }

    // 检查是否找到target
    return l < n && nums[(l + k) % n] == target ? (l + k) % n : -1;
}
```

**问题/优化方向**：
需要两次二分，虽然复杂度还是O(log n)，但代码逻辑分成了两个独立步骤。不够"直接"。

# 思路二：直接在旋转数组上二分（递归版，便于理解减治）

## 解题思路

**核心思想**：每次根据mid所在段和target所在段，直接判断target只可能在左半还是右半。

这题有递归解法吗？我一开始是抱着这个疑问来的。后来发现：递归版反而更容易理解，因为它把"原问题 -> 更小的子问题"这个减治过程显式化了。

**关键洞察**：二分的本质不是"找数"，而是"维护未决区间，每次砍掉一半不可能的区域"。在旋转数组里，砍的依据不再是"比大小"，而是"段归属 + 值域判断"。

**算法流程**：
1. 判断target在左段还是右段：`target >= nums[0]` ?
2. 判断mid在左段还是右段：`nums[mid] >= nums[0]` ? 或 `nums[mid] <= nums[n-1]` ?
3. 如果mid和target在同一段，做普通lower_bound；否则直接舍弃异段那一半

## 复杂度
- 时间复杂度：O(log n)
- 空间复杂度：O(log n)（递归栈深度）

## Code
```cpp
int search_recur(vector<int>& nums, int l, int r, int target){
    if (l == r) {
        return l;
    }

    int mid = (l + r) / 2;
    // 如果 target 在左边递增数组中
    if (target >= nums[0]) {
        // 说明 mid 在左边递增数组中
        if (nums[mid] >= nums[0]) {
            // 在左边递增数组中做 lower_bound
            if (nums[mid] >= target) {
                return search_recur(nums, l, mid, target);
            }
            else {
                return search_recur(nums, mid + 1, r, target);
            }
        }
        else {
            // mid 在右边递增数组中，直接舍弃右半部分
            return search_recur(nums, l, mid, target);
        }
    }
    else {
        // 如果在右边递增数组中
        if (nums[mid] <= nums[nums.size() - 1]) {
            // 在右边递增数组中做 lower_bound
            if (nums[mid] >= target) {
                return search_recur(nums, l, mid, target);
            }
            else {
                return search_recur(nums, mid + 1, r, target);
            }
        }
        else {
            // mid 在左边递增数组中，直接舍弃左半部分
            return search_recur(nums, mid + 1, r, target);
        }
    }
}

int search(vector<int>& nums, int target){
    int idx = search_recur(nums, 0, nums.size(), target);
    return idx < nums.size() && nums[idx] == target ? idx : -1;
}
```

**递归和迭代的关系**：
递归版可以拍平成迭代版，因为这是尾递归。每次递归只保留一个子问题，所以可以把"递归调用"改成"更新l/r后继续循环"。

# 思路三：直接在旋转数组上二分（迭代版，✅ 推荐解法）

## 解题思路

**核心思想**：递归版的迭代翻译，维护[l, r)未决区间，每次根据mid和target的段归属缩小区间。

我现在这版实现，就是每次循环都根据nums[mid]的信息做决策，一次砍掉当前问题的一半区间。

**为什么需要三层if/else？**
不是必须，而是这套框架里逻辑上确实有3个问题要回答：
1. **第一层**：target属于哪一段？
2. **第二层**：mid属于哪一段？
3. **第三层**：如果mid和target在同一段，再比较大小

第三层不是多余的。第二层只回答"是否同段"，第三层才回答"同段内答案在左还是右"。

**算法流程**：
1. 维护[l, r)未决区间（target还可能存在的位置）
2. 每次取mid，判断mid和target的段归属
3. 同段内做普通lower_bound，异段直接舍弃

## 复杂度
- 时间复杂度：O(log n)
- 空间复杂度：O(1)

## Code
```cpp
int search_iter(vector<int>& nums, int target) {
    int n = nums.size();
    if (n == 0) return -1;

    int l = 0, r = n;

    while (l < r) {
        int mid = l + (r - l) / 2;

        // 如果target在左边递增数组中
        if (target >= nums[0]) {
            // 如果mid在左边递增数组中
            if (nums[mid] >= nums[0]) {
                // 在左边递增数组中做lower_bound
                if (nums[mid] >= target) {
                    r = mid;
                } else {
                    l = mid + 1;
                }
            } else {
                // mid在右边递增数组中，直接舍弃右半
                r = mid;
            }
        } else {
            // target在右边递增数组中
            // 如果mid在右边递增数组中
            if (nums[mid] <= nums[n - 1]) {
                // 在右边递增数组中做lower_bound
                if (nums[mid] >= target) {
                    r = mid;
                } else {
                    l = mid + 1;
                }
            } else {
                // mid在左边递增数组中，直接舍弃左半
                l = mid + 1;
            }
        }
    }

    return l < n && nums[l] == target ? l : -1;
}
```

**问题/优化方向**：
这版代码虽然有点绕，但它最直接利用了"旋转数组分成两段"的结构信息，不需要额外找旋转点。

# 思路四：先确定target所在段，再普通二分（❌ 需要预处理）

## 解题思路

**核心思想**：先判断target应该在左段还是右段，然后把搜索区间缩到那个有序段里做普通二分。

这是我后来想到的："能不能有个更简单的实现？先通过预处理查找到target所在的位置，然后后面就针对这个缩小后的区间（只会是左边递增数组或者右边递增数组的子数组）。"

**算法流程**：
1. 先找旋转点k
2. 判断target在左段还是右段
3. 缩小区间到对应段，做普通二分

## 复杂度
- 时间复杂度：O(log n)
- 空间复杂度：O(1)

## Code
```cpp
int search(vector<int>& nums, int target) {
    int n = nums.size();
    if (n == 0) return -1;

    // 找旋转点
    int l = 0, r = n - 1;
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] > nums[r]) {
            l = mid + 1;
        } else {
            r = mid;
        }
    }
    int k = l;  // 旋转点

    // 判断target在哪个段，缩小搜索区间
    if (target >= nums[0]) {
        // 在左段：[0, k)
        r = k;
    } else {
        // 在右段：[k, n)
        l = k;
        r = n;
    }

    // 在选定段上做普通二分
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (nums[mid] >= target) {
            r = mid;
        } else {
            l = mid + 1;
        }
    }

    return l < n && nums[l] == target ? l : -1;
}
```

**问题/优化方向**：
虽然从"理解成本"上说可能更简单（后半段是纯普通二分），但代码总量未必更短，因为还是需要额外找旋转点。这是把复杂性从"比较规则"移到了"预处理找分界点"。

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 思路一：先找旋转点再虚拟二分 | O(log n) | O(1) | 思路清晰，分两步走 |
| 思路二：递归版（理解减治） | O(log n) | O(log n) | 递归版更容易理解"原问题 -> 子问题"的过程 |
| 思路三：直接在旋转数组上二分 | O(log n) | O(1) | **✅ 推荐解法**，最直接利用旋转性质，不需要额外找旋转点 |
| 思路四：先缩区间再普通二分 | O(log n) | O(1) | 后半段简单，但需要预处理找旋转点 |

# 关键词与核心洞察

## 关键词
- **二分减治**：不只是"排除一半"，而是"每次利用单调性提供的信息，排除一半'不可能包含答案'的区域"
- **旋转数组的段属性**：旋转数组由两个有序段组成，判断mid和target的段归属是关键
- **lower_bound思维**：二分不是找某个元素，而是找"第一个满足条件的位置"（分界点）
- **区间语义**：严格区分[l, r]和[l, r)，更新边界必须和区间语义匹配

## Insight
- **二分的本质**：不是"盯着target看"，而是"维护一个'答案仍可能存在'的未决区间"。对于lower_bound，未决区是"真假分界点还可能在哪"；对于旋转数组，未决区是"target还可能在哪"。
- **为什么是三层if/else**：第一层判断target属于哪一段，第二层判断mid属于哪一段，第三层在同一段内比较大小。第三层不是多余，第二层只回答"是否同段"，第三层才回答"同段内答案在哪"。
- **递归和迭代的关系**：递归版可以拍平成迭代版，因为这是尾递归。每次递归只保留一个子问题，所以可以把"递归调用"改成"更新l/r后继续循环"。
- **虚拟有序**：可以把旋转数组伪装成对target单调的数组：和target不同段的数，逻辑上视为+∞或-∞。

## 易错点
- **区间语义混乱**：脑子里是[l, r)，手上写的是闭区间更新（r = mid - 1），会导致越界或死循环
- **最终校验缺失**：lower_bound返回的是"候选位置"，必须再检查nums[l] == target，否则target不存在时会返回假答案
- **段判断的对称性**：如果左段判定用`nums[mid] >= nums[0]`（包含nums[0]），那右段判定对称地应该用`nums[mid] <= nums[n-1]`（包含nums[n-1]）
- **base case不统一**：递归版的base case要和区间语义匹配。[l, r)语义下，base case是`l == r`返回候选位置，不是`l == r`时直接判断`nums[l] == target`

---

**推荐**：面试中使用**思路三（迭代版）**，代码最简洁且最直接利用旋转数组性质。如果面试时需要解释思路，可以先讲递归版（思路二），因为它更容易理解"减治"的过程，然后再拍平成迭代版。
