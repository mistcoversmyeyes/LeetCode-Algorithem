# 34. 在排序数组中查找元素的第一个和最后一个位置 - 题解

## 题目描述

给你一个按照非递减顺序排列的整数数组 `nums`，和一个目标值 `target`。请你找出给定目标值在数组中的开始位置和结束位置。

如果数组中不存在目标值 `target`，返回 `[-1, -1]`。

你必须设计并实现时间复杂度为 `O(log n)` 的算法解决此问题。

**示例 1：**
```
输入：nums = [5,7,7,8,8,10], target = 8
输出：[3,4]
```

**示例 2：**
```
输入：nums = [5,7,7,8,8,10], target = 6
输出：[-1,-1]
```

**示例 3：**
```
输入：nums = [], target = 0
输出：[-1,-1]
```

---

# 思路一：三分支二分 + 左右扩展（❌ 失败尝试）

## 解题思路

**核心思想**：用标准三分支二分查找找到任意一个等于 target 的位置，然后向左右扩展找到边界。

这是我最自然的想法——第 35 题（搜索插入位置）我用三分支写得很顺，这题也想复用同样的套路：先找到 target，再往两边摸边界。

**算法流程**：
1. 三分支二分查找，`== target` 时 `break`
2. 从找到的位置向左扩展，直到 `nums[l-1] != target`
3. 从找到的位置向右扩展，直到 `nums[r+1] != target`

## Code
```cpp
class Solution {
public:
    vector<int> searchRange(vector<int>& nums, int target) {
        int l = 0;
        int r = nums.size() - 1;

        while (l <= r) {
            int mid = (l + r) / 2;
            if (target < nums[mid]) {
                r = mid - 1;
            }
            else if (target == nums[mid]) {
                break;  // 找到就停
            }
            else {
                l = mid + 1;
            }
        }
        // BUG 1: 没处理未找到的情况，l > r 时应返回 {-1, -1}

        while (l > 1 && nums[l - 1] == target) {  // BUG 2: l > 1 应为 l > 0
            l = l - 1;
        }
        while (r < nums.size() - 1 && nums[r + 1] == target) {
            r = r + 1;
        }
        return {l, r};
    }
};
```

**问题/优化方向**：

两个 bug：
1. **未处理未找到的情况**：如果 while 循环因 `l > r` 退出（没找到 target），代码仍然走到扩展逻辑，返回错误结果
2. **边界错误**：`l > 1` 应该是 `l > 0`。当 `l == 1` 且 `nums[0] == target` 时，不会向左扩展到 index 0

更根本的问题：**最坏 O(n)**。如果整个数组都是 target，左右扩展就退化成线性扫描，违反题目 O(log n) 的要求。

这就是三分支的致命缺陷——它"找到就停"，但这题需要的不是"找到"，而是"找到边界"。找到 target 后再打补丁扩展，是用错误的工具解决问题。

# 思路二：两次 lower_bound（✅ 推荐解法）

## 解题思路

**核心思想**：不找 target 本身，找边界。用同一个 `lower_bound`（第一个 >= target 的位置）调用两次，分别确定左右边界。

做完第 35 题后我理解了两分支 lower_bound 的不变量，这题就是它的直接应用：
- 左边界 = `lower_bound(target)` → 第一个 >= target 的位置
- 右边界 = `lower_bound(target + 1) - 1` → 第一个 >= target+1 的位置再减 1，就是最后一个 <= target 的位置

如果 `左边界 > 右边界`，说明 target 不存在。

**算法流程**：
1. `lower_bound(nums, target)` 找到第一个 >= target 的位置作为 `lower`
2. `lower_bound(nums, target + 1) - 1` 找到最后一个 <= target 的位置作为 `upper`
3. 如果 `lower <= upper`，返回 `{lower, upper}`；否则返回 `{-1, -1}`

**lower_bound 的不变量**：
```
0..l < target      （l 左边全排除）
r..n >= target     （r 及右边全确认）
```

从不变量推导一切：
- `r` 初始化 = `n`（还没确认任何元素 >= target）
- `nums[mid] >= target` → mid 属于右边，`r = mid`（保留 mid，它可能是答案）
- `nums[mid] < target` → mid 属于左边，`l = mid + 1`（排除 mid）
- 循环条件 `l < r`（灰色地带消失即结束）
- 结束时 `l == r`，两个已知区域碰头，`r` 就是第一个 >= target 的位置

## 复杂度
- 时间复杂度：O(log n) —— 两次二分查找
- 空间复杂度：O(1)

## Code
```cpp
class Solution {
public:
    vector<int> searchRange(vector<int>& nums, int target) {
        if (nums.empty()) {
            return {-1, -1};
        }

        auto lower_bound = [](const vector<int>& nums, int target){
            int l = 0;             // 不变量：nums[0..l) 全 < target
            int r = nums.size();   // 不变量：nums[r..n) 全 >= target

            while (l < r) {
                int mid = (l + r) / 2;
                if (nums[mid] >= target)
                    r = mid;
                else
                    l = mid + 1;
            }
            return r;  // l == r，两个已知区域碰头
        };

        int lower = lower_bound(nums, target);
        int upper = lower_bound(nums, target + 1) - 1;

        if (lower <= upper)
            return {lower, upper};
        else
            return {-1, -1};
    }
};
```

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 三分支 + 扩展 | O(n) 最坏 | O(1) | 直觉自然，但违反 O(log n) 要求 |
| 两次 lower_bound | O(log n) | O(1) | 一个模板解决，天然处理边界 |

# 关键词与核心洞察

## 关键词
- **lower_bound 复用**：同一个 lower_bound 函数，通过 `lower_bound(target)` 和 `lower_bound(target + 1) - 1` 分别得到左右边界。不需要写两个不同的函数，不需要"找 upper_bound"。
- **不变量驱动**：`0..l < target, r..n >= target`。从这一个不变量推导出所有边界条件——`r` 初始化为 `n`、`r = mid` 而非 `r = mid - 1`、`l < r` 而非 `l <= r`。记不变量，不记模板。
- **三分支的局限性**：三分支是"找到就停"，只能做精确查找。一旦需要找边界（本题），就必须加补丁，且最坏退化成 O(n)。

## Insight

**这道题是第 35 题的直接推论。**

第 35 题让我理解了 lower_bound 的不变量；第 34 题让我理解了为什么 lower_bound 是经典答案——因为"找边界"是比"找元素"更一般的问题，而 lower_bound 天然就是在找边界。

**思路转换的关键**：不要问"target 在哪"，问"第一个 >= target 的位置在哪"。问题的答案从"一个元素"变成"一个边界"，lower_bound 的不变量直接给出答案。

**l 和 r 不是搜索区间的端点**，而是两个独立的分界线，从两头向中间扩大已知区域。循环不是在"缩小搜索范围"，而是在"扩大已知区域"——左边已知全 < target，右边已知全 >= target，两个区域碰头时答案就出来了。

## 易错点
- **lambda 参数值拷贝**：`[](vector<int> nums, ...)` 每次调用拷贝整个数组。必须用 `const vector<int>& nums`。
- **`r` 初始化为 `nums.size()` 不是 `nums.size() - 1`**：因为 target 可能比所有元素都大，第一个 >= target 的位置就是 `n`（不存在）。用左闭右开区间 `[0, n)` 天然覆盖这个情况。
- **空数组特判**：`nums.empty()` 时直接返回 `{-1, -1}`，否则 `lower_bound` 返回 0，`upper` 可能为 -1，逻辑仍然正确（`lower > upper`），但提前返回更清晰。

---

**推荐**：掌握 lower_bound 的不变量后，本题就是"调用两次，完事"。面试中展示不变量推导过程会加分。
