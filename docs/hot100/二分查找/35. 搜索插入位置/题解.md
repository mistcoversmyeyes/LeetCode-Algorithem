# 35. 搜索插入位置 - 题解

## 题目描述

给定一个排序数组和一个目标值，在数组中找到目标值，并返回其索引。如果目标值不存在于数组中，返回它将会被按顺序插入的位置。

请必须使用时间复杂度为 `O(log n)` 的算法。

**示例 1：**
```
输入: nums = [1,3,5,6], target = 5
输出: 2
```

**示例 2：**
```
输入: nums = [1,3,5,6], target = 2
输出: 1
```

**示例 3：**
```
输入: nums = [1,3,5,6], target = 7
输出: 4
```

---

# 思路一：三分支递归二分查找（✅ 推荐解法）

## 解题思路

**核心思想**：维护一个不变式（invariant），让代码的 base case 可以直接返回答案，无需额外判断。

我最初的想法是用递归来实现二分查找，但不同于常见的 lower_bound 写法，我选择了**三个分支**（`<`、`=`、`>`）的递归策略。

**关键洞察——不变式（Invariant）**：

每次进入递归时，保证以下性质成立：
- `[0, left-1]` 区间的所有值都 **小于** `target`
- `[right+1, n-1]` 区间的所有值都 **大于** `target`

当递归到达 base case（`left > right`）时，两个区间"碰头"了：
- `left` 是右区间的起点（`right + 1`）
- `left` 左边的所有值都 `< target`
- `left` 右边的所有值都 `> target`

**因此 `left` 恰好就是插入位置！**

**算法流程**：
1. 计算 `mid = (left + right) / 2`
2. 如果 `target < nums[mid]`：递归左半部分，`right = mid - 1`
3. 如果 `target > nums[mid]`：递归右半部分，`left = mid + 1`
4. 如果 `target == nums[mid]`：直接返回 `mid`
5. Base case：`left > right` 时返回 `left`

## 复杂度
- 时间复杂度：O(log n) —— 每次将搜索范围减半
- 空间复杂度：O(log n) —— 递归栈深度

## Code
```cpp
class Solution {
public:
    int searchInsert_recursion(vector<int>& nums, int target, int left, int right) {
        // Base case：当 left > right 时，left 就是插入位置
        // 因为 invariant 保证 [0, left-1] < target 且 [right+1, n-1] > target
        // 而 right + 1 == left，所以 left 左边都小于 target，右边都大于 target
        if (left > right) {
            return left;
        }

        int mid = (right + left) / 2;

        if (target < nums[mid]) {
            // 目标在左半部分，right 收缩到 mid-1
            // 不变式依然成立：[right+1, n-1] = [mid, n-1] 都 > target
            return searchInsert_recursion(nums, target, left, mid - 1);
        }
        else if (target == nums[mid]) {
            // 找到目标，直接返回
            return mid;
        }
        else {
            // 目标在右半部分，left 收缩到 mid+1
            // 不变式依然成立：[0, left-1] = [0, mid] 都 < target
            return searchInsert_recursion(nums, target, mid + 1, right);
        }
    }

    int searchInsert(vector<int>& nums, int target) {
        return searchInsert_recursion(nums, target, 0, nums.size() - 1);
    }
};
```

**为什么选三分支？**

这是 Linus Torvalds "好品味"的体现——**让特殊情况消失，而不是增加条件判断**。

- 二分支（`<` 和 `>=`）需要额外处理 `==` 时是否继续左移、base case 需判断是"找到"还是"未找到"、还要处理越界
- 三分支把 `==` 单独拎出来，base case 直接返回 `left`，**没有任何特殊情况**

# 思路二：两分支 lower_bound（通用二分模板）

## 解题思路

**核心思想**：只问一个问题——"nums[mid] 够不够大？"，不单独处理 `==`。

最初我觉得这种写法难写对、容易搞错边界，所以一度放弃了它。但在做第 34 题（查找元素的第一个和最后一个位置）时，我发现三分支的致命缺陷：**找到 target 就停下来，无法定位边界**。遇到重复元素，只能靠"找到后左右扩展"的补丁，最坏退化成 O(n)。

而两分支天然解决边界问题——它找到等于 target 的元素时**不停下来**，继续收缩，直到逼出精确边界。

**不变量（这是一切的起点）**：

```
0..l < target    （l 左边全排除）
r..n >= target   （r 及右边全确认）
```

`[l, r)` 是还没定论的灰色地带。循环每一步缩小它，直到 `l == r` 灰色地带消失，答案就是 `l`。

**从不变量推导一切（记不变量，不记模板）**：

1. `r` 初始化 = `n`（还没确认任何元素 >= target，所以"已确认"区间从 `n` 开始。同时 target 可能比所有元素都大，插入位置就是 `n`）
2. `l` 初始化 = `0`
3. `nums[mid] < target` → mid 属于左边（< target），排除它，`l = mid + 1`
4. `nums[mid] >= target` → mid 属于右边（>= target），保留它，`r = mid`（不是 `mid - 1`，因为 mid 本身可能是答案）
5. 循环条件 `l < r`（`l == r` 时灰色地带消失，结束）

**每一行代码都是从不变量推出来的，不存在"记错"的问题。**

## 复杂度
- 时间复杂度：O(log n)
- 空间复杂度：O(1)

## Code
```cpp
class Solution {
public:
    int searchInsert(vector<int>& nums, int target) {
        int l = 0, r = nums.size();  // r = n，不是 n-1
        while (l < r) {              // 灰色地带还在
            int mid = (l + r) / 2;
            if (nums[mid] < target)
                l = mid + 1;         // mid 太小，排除
            else
                r = mid;             // mid 可能是答案，保留
        }
        return l;                    // l == r，灰色地带消失
    }
};
```

**为什么之前觉得难写对？**

因为之前试图**背模板**——`l < r` 还是 `l <= r`？`r = mid` 还是 `r = mid - 1`？这些细节单独记忆确实容易搞混。但如果从不变量出发推导，每个选择都有唯一正确答案，根本不需要记。

**与第 34 题的联系**：

这个模板能直接解决"查找元素的第一个和最后一个位置"：
```cpp
int left = lower_bound(nums, target);          // 第一个 >= target
int right = lower_bound(nums, target + 1) - 1; // 第一个 >= target+1 再减 1
if (left > right) return {-1, -1};
return {left, right};
```

一个模板打天下，不用每题重新想。

# 思路三：迭代二分查找（工程实际使用）

## 解题思路

**核心思想**：同样的三分支逻辑，改成迭代实现，避免递归栈溢出风险。

在实际工程中，递归二分查找几乎不用。迭代写法使用同样的 invariant，代码更简洁高效。

## 复杂度
- 时间复杂度：O(log n)
- 空间复杂度：O(1) —— 只用了常数额外空间

## Code
```cpp
class Solution {
public:
    int searchInsert(vector<int>& nums, int target) {
        int left = 0, right = nums.size() - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;  // 防溢出

            if (target < nums[mid]) {
                right = mid - 1;
            } else if (target > nums[mid]) {
                left = mid + 1;
            } else {
                return mid;  // 找到目标
            }
        }

        // left > right 时，left 就是插入位置
        // invariant: [0, left-1] < target && [right+1, n-1] > target
        // 且 right + 1 == left，所以 left 是答案
        return left;
    }
};
```

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 三分支递归 | O(log n) | O(log n) | 代码清晰，invariant 直接导出 base case |
| 两分支 lower_bound | O(log n) | O(1) | 通用模板，天然支持边界查找，一招通吃 |
| 三分支迭代 | O(log n) | O(1) | 直觉友好，适合精确查找 |

| | 三分支 | 两分支 |
|---|---|---|
| 思路 | 找到就停 | 不断缩小范围 |
| 处理重复元素 | 需要补丁（左右扩展） | 天然支持 |
| 适用范围 | 精确查找 | 精确查找 + 边界查找 |
| 出错点 | 少，但扩展性差 | `l < r` vs `l <= r`、`r = mid` vs `r = mid-1` 容易写错（但从不变量推导就不会错） |

**推荐**：面试中如果只需精确查找，**三分支**更直觉；如果涉及边界查找（如第 34 题），**两分支 lower_bound** 是唯一正解。长期来看，掌握两分支的不变量推导法更有价值。

# 关键词与核心洞察

## 关键词
- **不变量（Invariant）**：三分支的不变量是 `[0, l-1] < target` 且 `[r+1, n-1] > target`；两分支的不变量是 `0..l < target` 且 `r..n >= target`。不变量不是事后验证，而是设计的起点——所有边界条件都从它推导出来。
- **记不变量，不记模板**：两分支 lower_bound 难写对，是因为很多人试图背 `l < r` / `r = mid` 这些细节。但如果从不变量出发推导，`r` 初始化为 `n`（因为还没确认任何元素）、`r = mid`（因为 mid 本身可能是答案）、`l < r`（灰色地带消失即结束）——每一行都有唯一正确答案。
- **三分支 vs 两分支**：三分支是"找到就停"，两分支是"找边界"。边界是更一般的问题，精确查找只是边界的特例。

## Insight

**三分支是"我在找 target"，两分支是"我在找一个边界"。**

这是这次做第 34 题时的关键认知升级。三分支对第 35 题没问题，但一到需要处理重复元素的边界问题，就必须加补丁（找到后左右扩展），最坏退化 O(n)。两分支的 lower_bound 天然就是在找边界，一个模板解决：
- 第 35 题：`lower_bound(target)` 就是插入位置
- 第 34 题：左边界 = `lower_bound(target)`，右边界 = `lower_bound(target+1) - 1`

**两分支难写对的本质原因**：它更抽象。你在维护一个不变量（"答案一定在 `[l, r)` 中"），而不是在做模式匹配。但正因为抽象，它才通用。

**解决"难写对"的方法**：不要背模板，从不变量推导一切。不变量 `0..l < target, r..n >= target` 决定了：
1. `r = n`（不是 `n-1`）
2. `nums[mid] < target` → `l = mid + 1`（排除 mid）
3. `nums[mid] >= target` → `r = mid`（保留 mid）
4. `l < r`（不是 `l <= r`）
5. 返回 `l`

五条规则，全部从一个不变量推出，不存在"长时间不写就忘了"的问题。

## 易错点
- **`r` 的初始值**：两分支必须 `r = nums.size()`，不是 `nums.size() - 1`。因为插入位置可能在数组末尾之后（如 `[1,3,5,6]` 中 target=7，答案是 4）。三分支用 `r = nums.size() - 1` 加 `l <= r`，靠 `return l` 兜住；两分支用 `r = nums.size()` 加 `l < r`，不变量天然覆盖。
- **`r = mid` 不是 `r = mid - 1`**：两分支中 `nums[mid] >= target` 时，mid 本身可能是答案，必须保留在搜索范围内。
- **整数溢出**：`mid = (l + r) / 2` 在 `l` 和 `r` 很大时可能溢出。应使用 `mid = l + (r - l) / 2`。

---

**推荐**：掌握两分支 lower_bound 的不变量推导法，面试中遇到任何二分变体都能从容应对。精确查找用三分支更直觉，边界查找用两分支是唯一正解。
