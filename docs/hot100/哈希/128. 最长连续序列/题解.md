**128.** 最长连续序列 - 题解
====

# 题目描述

给定一个未排序的整数数组 `nums`，找出数字连续的最长序列的长度。

**要求**：请设计时间复杂度为 O(n) 的算法。

**示例**：
```
输入：nums = [100,4,200,1,3,2]
输出：4
解释：最长数字连续序列是 [1, 2, 3, 4]。它的长度为 4。
```

---

# 思路一：排序 + 双指针扫描

## 解题思路

**核心思想**：先排序让连续的元素在物理上相邻，然后用一次线性扫描找出所有连续序列。

这是我最自然的想法：虽然题目说了不要排序，但是我最自然的思路还是先排序，这样所有的连续子序列中的元素都会是相邻的，避免每次都要从剩余的数组中搜索出能够与当前子序列首/尾接起来的数字。

**算法流程**：
1. 对数组进行排序（升序）
2. 使用双指针（或单指针 + 当前长度计数）线性扫描排序后的数组
3. 判断当前元素与前一个元素的关系：
   - 连续（`nums[i] == nums[i-1] + 1`）：当前序列长度 +1
   - 重复（`nums[i] == nums[i-1]`）：跳过，不改变当前长度
   - 断开（其他情况）：更新最大长度，重置当前长度为 1
4. 处理完所有元素后，再次更新最大长度（处理最后一个序列）

## 复杂度
- 时间复杂度：O(n log n) - 主要来自排序
- 空间复杂度：O(1) - 排序通常是原地排序（`std::sort` 是内省排序，空间复杂度 O(log n)）

## Code
```cpp
#include <vector>
#include <algorithm>

using namespace std;

class Solution {
public:
    int longestConsecutive(vector<int>& nums) {
        if (nums.size() == 0) {
            return 0;
        }

        sort(nums.begin(), nums.end());

        int max_length = 1;
        int cur_length = 1;

        for (int i = 1; i < nums.size(); i++) {
            if (nums[i] == nums[i - 1] + 1) {
                // 连续：当前序列长度 +1
                cur_length++;
            } else if (nums[i] == nums[i - 1]) {
                // 重复：跳过
                continue;
            } else {
                // 断开：更新最大长度，重置当前长度
                if (cur_length >= max_length) {
                    max_length = cur_length;
                }
                cur_length = 1;
            }
        }

        // 处理最后一个序列
        if (cur_length >= max_length) {
            max_length = cur_length;
        }

        return max_length;
    }
};
```

**问题/优化方向**：
- ✅ 代码简洁，逻辑清晰
- ✅ 实际运行性能好（通过了 OJ）
- ✅ 内存占用小（原地排序）
- ❌ 理论时间复杂度 O(n log n)，不满足题目要求的 O(n)

# 思路二：哈希表 + 序列起点判断

## 解题思路

**核心思想**：用哈希表 O(1) 判断元素是否存在，只从序列起点开始遍历，确保每个元素只被访问一次。

在面试官的引导下，我理解了哈希法的核心洞察：**排序是预处理的一种方式（让连续元素物理相邻），但哈希表是另一种预处理方式（让连续元素逻辑相邻）**。

关键问题变成了：**如何避免重复计算同一个序列？**

例如数组 `[100, 4, 200, 1, 3, 2]`，序列 `[1, 2, 3, 4]`：
- 从 1 开始会遍历到 2, 3, 4
- 从 2 开始也会遍历到 3, 4
- 从 3 开始还会遍历到 4

**关键突破**：什么情况下一个数是"序列的起点"？
- 如果 `x-1` 不在集合里，则 `x` 是序列起点
- 只从起点开始向后找，保证每个序列只被遍历一次

**算法流程**：
1. 构建哈希集合，存储所有出现过的数字（去重）
2. 遍历哈希集合，找到所有序列起点（`x-1` 不存在的数）
3. 从每个起点开始，向后依次查找 `x+1, x+2, ...` 直到断开
4. 计算每个序列的长度，取最大值

## 复杂度
- 时间复杂度：O(n) - 外层遍历 O(n)，内层查找总共 O(n)（每个元素最多访问一次）
- 空间复杂度：O(n) - 哈希集合存储所有元素

## Code
```cpp
#include <vector>
#include <unordered_set>

using namespace std;

class Solution {
public:
    int longestConsecutive(vector<int>& nums) {
        // 构建哈希集合
        unordered_set<int> num_set;
        for (int num : nums) {
            num_set.insert(num);
        }

        int max_length = 0;

        // 遍历哈希集合，找到序列起点
        for (int num : num_set) {
            // 判断是否为序列起点：num-1 不存在
            if (num_set.find(num - 1) == num_set.end()) {
                int cur_length = 1;

                // 从起点向后查找
                for (int cur = num;
                     num_set.find(cur + 1) != num_set.end();
                     cur++) {
                    cur_length++;
                }

                max_length = max(max_length, cur_length);
            }
        }

        return max_length;
    }
};
```

**问题/优化方向**：
- ✅ 理论时间复杂度 O(n)，满足题目要求
- ✅ 逻辑清晰，易于理解
- ❌ **实际运行超时（TLE 80/84）**
- ❌ 内存占用远大于排序方案

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 实际性能 | 特点 |
|------|-----------|-----------|---------|------|
| 排序 + 双指针 | O(n log n) | O(1) | ✅ 快 | 代码简洁，内存友好，工程推荐 |
| 哈希表 + 起点 | O(n) | O(n) | ❌ 超时 | 理论最优，实际性能差 |

# 关键要点

## 1. 理论复杂度 ≠ 实际性能

**实践再次证明了一个真理**：

> "Theory and practice sometimes clash. Theory loses. Every single time."
> — Linus Torvalds

O(n) 的哈希方案在理论上应该更快，但实际运行却不如 O(n log n) 的排序方案。**为什么会这样？**

| 因素 | 哈希方案 | 排序方案 |
|------|---------|---------|
| 常数因子 | 大（哈希计算、冲突处理、内存跳转） | 小（连续内存访问） |
| CPU 缓存 | 不友好（随机访问） | 友好（顺序访问） |
| 内存开销 | O(n) 额外空间 | O(1) 或 O(log n) |

## 2. 空间换时间 ≠ 总是划算

我的哈希方案：
- 用了 O(n) 额外空间
- 换来的却是更慢的速度

**这就是我之前说的："除非这个空间值得使用。"**

在这道题上，**空间换时间不值得。**

## 3. 题目约束 ≠ 实际最优

题目要求 O(n)，但：
- 测试用例规模不够大，体现不出 O(n) 的优势
- LeetCode 的测试环境可能更适合排序的缓存友好特性

**数据规模的影响**：
```
n = 1,000:     排序更快 ✓
n = 10,000:    排序更快 ✓
n = 100,000:   排序可能更快（取决于常数因子）
n = 1,000,000: O(n) 开始显现优势
n = 10,000,000: O(n) 应该明显更快
```

O(n log n) 的 log n 增长很慢，需要 n 很大才能看出差距。

## 4. 算法技巧的本质

无论是窗口、预处理，还是其他数组技巧，**本质上都是如何构造一个高效且逻辑较为简单的遍历**：

- **排序方案**：让连续元素在物理上相邻 → 遍历时能连续扫描
- **哈希方案**：让连续元素在逻辑上相邻 → O(1) 判断后继是否存在

两种方案都在做同一件事：**构造一个"高效"且"不重复、不遗漏"的遍历策略。**

# 工程实践建议

**如果这是生产环境的代码，我会这样选择：**

1. **数据量小（< 10,000）** → 排序方案
   - 代码简单、内存友好、实际更快

2. **数据量大（> 100,000）** → 哈希方案
   - 复杂度优势开始显现

3. **不确定数据规模** → 两种都实现，用实际数据测试
   - 让 benchmark 决定

**或者更务实的方法：先写排序，如果 profiling 发现性能瓶颈，再优化成哈希。**

**这就叫：既有理论高度，又有工程判断。**
