# 49. 字母异位词分组 - 题解

## 题目描述

给你一个字符串数组 `strs`，请你将字母异位词组合在一起。可以按任意顺序返回结果列表。

字母异位词是由重新排列源单词的字母得到的一个新单词，所有源单词中的字母通常恰好只用一次。

**示例 1**：
```
输入: strs = ["eat","tea","tan","ate","nat","bat"]
输出: [["bat"],["nat","tan"],["ate","eat","tea"]]
```

**示例 2**：
```
输入: strs = [""]
输出: [[""]]
```

**示例 3**：
```
输入: strs = ["a"]
输出: [["a"]]
```

**约束**：
- `1 <= strs.length <= 10⁴`
- `0 <= strs[i].length <= 100`
- `strs[i]` 仅包含小写字母

---

# 思路一：暴力法

## 解题思路

**核心思想**：对每个字符串，遍历数组找到它的所有字母异位词，组成一组。

这是我最自然的想法：对于每个词，找到它的字母异位词，然后放入结果临时数组中，然后删除选中的词。

**算法流程**：
1. 外层循环遍历每个字符串 `s`
2. 内层循环遍历所有未被分组的字符串 `t`
3. 判断 `s` 和 `t` 是否是字母异位词（排序后比较，或字符计数比较）
4. 将异位词加入当前分组，标记已处理

## 复杂度
- 时间复杂度：O(n² × k) —— n 个字符串，两两比较，每次比较 O(k)
- 空间复杂度：O(n) —— `used[]` 数组

## Code
```cpp
class Solution {
public:
    vector<vector<string>> groupAnagrams(vector<string>& strs) {
        vector<vector<string>> result;
        vector<bool> used(strs.size(), false);

        for (int i = 0; i < strs.size(); i++) {
            if (used[i]) continue;

            vector<string> group;
            group.push_back(strs[i]);
            used[i] = true;

            for (int j = i + 1; j < strs.size(); j++) {
                if (used[j]) continue;
                if (isAnagram(strs[i], strs[j])) {
                    group.push_back(strs[j]);
                    used[j] = true;
                }
            }

            result.push_back(group);
        }

        return result;
    }

    bool isAnagram(const string& a, const string& b) {
        if (a.size() != b.size()) return false;
        int count[26] = {0};
        for (char c : a) count[c - 'a']++;
        for (char c : b) {
            if (--count[c - 'a'] < 0) return false;
        }
        return true;
    }
};
```

**问题/优化方向**：
存在大量重复比较，时间复杂度过高。每次判断两个字符串是否为字母异位词时，都要重新计算字符计数，造成重复计算。应该考虑预处理优化。

# 思路二：自定义哈希函数（❌ 失败尝试）

## 解题思路

**核心思想**：设计一个哈希函数 `hash(str)`，让字母异位词映射到同一个整数，然后用哈希表记录每个哈希值对应的字符串索引。

我简单的分析了一下，选中某个词的其它异位词的方法可以使用链哈希表优化。我们构造一个哈希函数 `hash(str)`，相同的词具有相同的字母组成，然后先遍历一遍输入数组，记录每个 hash 值相同的词的位置 idx。

**尝试过程**：
1. 想到用哈希表优化暴力法中的重复计算问题
2. 尝试了**字符求和法**：
   ```cpp
   int hash(string str) {
       int hash_val = 0;
       for (char ch : str) {
           hash_val += (int)ch;  // 累加字符的 ASCII 值
       }
       return hash_val;
   }
   ```
3. 发现问题：会有**哈希碰撞**
   - "ac" = 97 + 99 = 196
   - "bb" = 98 + 98 = 196
   - 不是字母异位词的词被分到了一组！

# 思路三：哈希表 + 排序（Canonical Form）

## 解题思路

**核心思想**：将每个字符串排序后作为哈希表的 key，字母异位词排序后结果相同。

字母异位词的本质是包含相同的字母，只是顺序不同。例如：
- "eat"、"tea"、"ate" 排序后都是 "aet"
- 排序后的字符串就是完美的标准形式（Canonical Form）

这是在面试官引导下发现的方法：
- 面试官问："字母异位词有什么共同特点？"
- 我答："它们包含的字母完全一样，只是顺序不同"
- 面试官问："如果我想让 'eat'、'tea'、'ate' 变成同一个字符串，应该怎么处理？"
- 我恍然大悟："排序！"

**算法流程**：
1. 遍历字符串数组 `strs`
2. 对每个字符串排序，得到 key
3. 用哈希表 `unordered_map<string, vector<int>>` 记录：key → 原始字符串的索引
4. 遍历哈希表，根据索引收集结果

## 复杂度
- 时间复杂度：O(n × k log k)
  - n 个字符串
  - 每个字符串排序 O(k log k)，k 是字符串长度
  - 哈希表操作平均 O(1)
- 空间复杂度：O(n × k)
  - 哈希表存储 n 个 key（排序后的字符串）
  - 存储所有索引

## Code
```cpp
class Solution {
public:
    vector<vector<string>> groupAnagrams(vector<string>& strs) {
        unordered_map<string, vector<int>> chrs2pos;
        int index = 0;

        for (string str : strs) {
            sort(str.begin(), str.end());  // 排序作为 key

            if (chrs2pos.find(str) == chrs2pos.end()) {
                chrs2pos.insert({str, vector<int>()});
            }
            chrs2pos[str].push_back(index);
            index++;
        }

        vector<vector<string>> result;
        for (const auto& item : chrs2pos) {
            vector<string> tmp;
            for (int idx : item.second) {
                tmp.push_back(strs.at(idx));
            }
            result.push_back(tmp);
        }

        return result;
    }
};
```

**问题/优化方向**：排序的时间复杂度是 O(k log k)，可以考虑用计数方法优化到 O(k)（见思路四）。

# 思路四：哈希表 + 计数签名

## 解题思路

**核心思想**：用字符计数作为 key，避免排序，将时间复杂度降到 O(k)。

由于只有小写字母，可以用一个 26 元素的数组表示字符计数：
- "eat" → `{1,0,0,...,0,1,0,...,0,1,0,...}`（a:1, e:1, t:1）
- "tea" → `{1,0,0,...,0,1,0,...,0,1,0,...}`（相同）

将计数数组编码为字符串作为哈希表的 key。这实际上就是思路二"字符计数"的完善版本 —— 我们不再求和（避免碰撞），而是保留完整的计数信息。

**算法流程**：
1. 遍历字符串数组 `strs`
2. 对每个字符串统计 26 个字母的出现次数
3. 将计数数组编码为字符串 key（如 "1#0#2#..."）
4. 用哈希表 `unordered_map<string, vector<string>>` 记录：key → 原始字符串
5. 直接返回哈希表的 values

## 复杂度
- 时间复杂度：O(n × (k + 26)) = O(n × k)
  - 遍历每个字符串 O(k)
  - 构造 key O(26)
- 空间复杂度：O(n × k)

## Code
```cpp
class Solution {
public:
    vector<vector<string>> groupAnagrams(vector<string>& strs) {
        unordered_map<string, vector<string>> groups;

        for (string& s : strs) {
            int count[26] = {0};
            for (char c : s) {
                count[c - 'a']++;
            }

            // 将计数数组编码为字符串
            string key;
            for (int i = 0; i < 26; i++) {
                key += '#' + to_string(count[i]);
            }

            groups[key].push_back(s);
        }

        vector<vector<string>> result;
        for (auto& pair : groups) {
            result.push_back(pair.second);
        }

        return result;
    }
};
```

**问题/优化方向**：
虽然时间复杂度更优，但常数较大。在实际测试中，由于 k 通常较小（字符串长度较短），排序方法可能更快。面试中推荐思路三，代码更简洁。

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 暴力法 | O(n² × k) | O(n) | 最自然的想法，但低效 |
| 自定义哈希函数 | - | - | ❌ 失败尝试：找不到完美的哈希函数 |
| 哈希表 + 排序 | O(n × k log k) | O(n × k) | **推荐**：简洁、高效、易维护 |
| 哈希表 + 计数 | O(n × k) | O(n × k) | 理论时间复杂度更优，但常数大 |

# 关键要点

1. **Canonical Form（规范化）思想**：
   这道题的核心突破是 **Canonicalization（规范化）** 范式：把复杂判等问题降维为"标准形式上的相等"，再交给通用基础设施（哈希表）处理。
   - 字母异位词 → 排序 → 相同的 key
   - 本质：先转换数据表示，让通用容器自然工作
   - 这比"自定义哈希函数"处于更高的抽象层级

2. **为什么字符求和不行**：
   - 简单的字符求和会丢失信息："ac" 和 "bb" 的和相同
   - 正确的做法是保留完整的计数信息（思路四）或转换为标准形式（思路三）
   - 这体现了"不要丢失信息"的设计原则

3. **哈希表的正确使用方式**：
   - ❌ 错误：自定义 Hasher 让不同的 key 映射到相同的哈希值（但 KeyEqual 仍会判定它们不相等）
   - ✅ 正确：转换数据到标准形式，用默认的 Hasher 和 KeyEqual
   - `unordered_map` 的语义由 `(Hash, KeyEqual)` 共同决定

4. **算法设计的抽象层级**：
   > **"Bad programmers worry about the code. Good programmers worry about data structures."** —— Linus Torvalds

   这道题体现了选择正确抽象层级的重要性：
   - **低层级**：设计复杂的哈希函数（思路二，失败）
   - **高层级**：调整数据表示（思路三，成功）

5. **面试经验教训**：
   - 卡在某个思路上 6-7 分钟很正常，关键是保持冷静
   - 暴力法作为起点是合理的，但要思考如何优化重复计算
   - 从"最自然的想法"出发，逐步优化到最优解
   - 面试官的引导（如"字母异位词有什么共同特点"）是关键提示

---

**推荐**：面试中使用**思路三（哈希表 + 排序）**，代码简洁、高效、易解释，充分体现了规范化思想。思路四适合作为进一步优化的讨论点。
