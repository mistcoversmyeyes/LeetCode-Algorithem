# 230. 二叉搜索树中第 K 小的元素 - 题解

## 题目描述

给定一个二叉搜索树的根节点 `root` ，和一个整数 `k` ，请你设计一个算法查找其中第 `k` 小的元素（从 1 开始计数）。

**示例 1**：
```
输入: root = [3,1,4,null,2], k = 1
输出: 1
```

**示例 2**：
```
输入: root = [5,3,6,2,4,null,null,1], k = 3
输出: 3
```

**约束**：
- 树中的节点数为 `n`
- `1 <= k <= n <= 10⁴`
- `0 <= Node.val <= 10⁴`

---

# 导读

## 关键词
- **中序遍历**：BST 的中序遍历（左 → 根 → 右）会按**从小到大**的顺序输出节点值。这是 BST 最核心的性质。
- **辅助变量的传递方式**：在递归遍历中添加辅助变量时，必须明确是值传递还是引用传递。值传递每层独立，引用传递全局共享。
- **辅助变量的更新位置**：在遍历框架中添加辅助逻辑时，更新代码的位置决定了其生效时机（前序/中序/后序）。

## Insight
**BST 查找第 K 小的本质**：
- 表层理解：遍历整个树，排序，取第 k 个
- **深层理解**：利用 BST 的性质，中序遍历天然有序，只需遍历到第 k 个节点即可提前终止（虽然本题实现中没有做提前终止优化）

## 易错点
- **值传递 vs 引用传递**：`int count`（值传递）不会在递归调用间累积计数，必须用 `int& count`（引用传递）
- **注释准确性**：代码是中序遍历（从小到大），但注释写成了"从大到小"，造成误导

---

# 思路一：中序遍历 + 计数器

## 解题思路

**核心思想**：BST 的中序遍历（左 → 根 → 右）会按从小到大的顺序输出节点值，只需在遍历时计数，找到第 k 个即可。

这是我最自然的想法：二叉搜索树的性质就是左子树所有节点小于根节点，右子树所有节点大于根节点。那么按"左 → 根 → 右"的顺序遍历，就是从小到大的有序序列。

**算法流程**：
1. 对 BST 进行中序遍历
2. 用 `count` 变量记录已经访问了多少个节点
3. 当 `count == k` 时，当前节点就是第 k 小的元素

## 复杂度
- 时间复杂度：O(H + k)
  - H 是树的高度，最坏情况 O(n)（树退化为链表）
  - 最好情况只需遍历 k 个节点
- 空间复杂度：O(H)
  - 递归栈的深度，H 是树的高度

## Code
```cpp
/**
 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     TreeNode *left;
 *     TreeNode *right;
 *     TreeNode() : val(0), left(nullptr), right(nullptr) {}
 *     TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
 *     TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
 * };
 */
class Solution {
public:
    int kthSmallest(TreeNode* root, int k) {
        int res = 0;
        int count = 0;
        dfs(root, k, count, res);
        return res;
    }

    // 从小到大搜索以 root 为根节点的二叉树，并且同时记录搜索到的节点的个数
    void dfs(TreeNode* root, const int& k, int& count, int& res) {
        if (root == nullptr) {
            return;
        }

        dfs(root->left, k, count, res);  // 先遍历左子树（小的）

        count++;  // 访问当前节点，计数加 1
        if (count == k) {
            res = root->val;  // 找到第 k 小的元素
            return;
        }

        dfs(root->right, k, count, res);  // 再遍历右子树（大的）
    }
};
```

**问题/优化方向**：
- 当前实现找到答案后没有提前终止递归，会继续遍历剩余节点。可以通过添加 `bool& found` 标志位来提前终止，但不影响正确性。

# 思路二：迭代式中序遍历（栈实现）

## 解题思路

**核心思想**：用栈模拟递归过程，显式控制遍历流程。

递归的本质是系统维护的调用栈，我们可以自己维护一个栈来模拟中序遍历。这种写法的优势是可以更方便地控制提前终止。

**算法流程**：
1. 初始化空栈，指针 `curr` 指向根节点
2. 循环条件：`curr` 不为空 或 栈不为空
3. 将 `curr` 的所有左孩子入栈
4. 弹出栈顶，计数加 1
5. 如果计数等于 k，返回该节点值
6. `curr` 指向右孩子

## 复杂度
- 时间复杂度：O(H + k)
- 空间复杂度：O(H) —— 栈的深度

## Code
```cpp
class Solution {
public:
    int kthSmallest(TreeNode* root, int k) {
        stack<TreeNode*> stk;
        TreeNode* curr = root;
        int count = 0;

        while (curr != nullptr || !stk.empty()) {
            // 一直往左走，将路径上的节点入栈
            while (curr != nullptr) {
                stk.push(curr);
                curr = curr->left;
            }

            // 弹出栈顶（当前最小的未访问节点）
            curr = stk.top();
            stk.pop();

            count++;
            if (count == k) {
                return curr->val;  // 找到第 k 小的元素
            }

            // 转向右子树
            curr = curr->right;
        }

        return -1;  // 不会执行到这里，因为 k 保证有效
    }
};
```

**问题/优化方向**：
- 迭代写法可以更自然地提前终止（找到后直接 return），不需要额外的标志位。

# 思路三：记录子树节点数（适用于多次查询）

## 解题思路

**核心思想**：预处理每个节点的子树节点数，然后通过二分查找快速定位第 k 小的元素。

如果需要**多次查询**不同 k 的结果，每次都 O(k) 遍历效率不高。可以预处理每个节点记录其左子树的节点数，查询时类似二分查找。

**算法流程**：
1. **预处理**：遍历树，计算每个节点的左子树节点数 `leftCount`
2. **查询**：
   - 如果 `k == leftCount + 1`，当前节点就是答案
   - 如果 `k <= leftCount`，在左子树中查找第 k 小
   - 如果 `k > leftCount + 1`，在右子树中查找第 `k - leftCount - 1` 小

## 复杂度
- **预处理**：
  - 时间复杂度：O(n)
  - 空间复杂度：O(n) —— 需要额外存储节点数
- **每次查询**：
  - 时间复杂度：O(H)
  - 空间复杂度：O(1)

## Code
```cpp
class Solution {
private:
    // 记录每个节点的左子树节点数
    unordered_map<TreeNode*, int> leftCount;

    // 预处理：计算每个节点的左子树节点数
    int countNodes(TreeNode* root) {
        if (root == nullptr) return 0;
        int left = countNodes(root->left);
        int right = countNodes(root->right);
        leftCount[root] = left;
        return left + right + 1;
    }

public:
    int kthSmallest(TreeNode* root, int k) {
        countNodes(root);  // 预处理
        return find(root, k);
    }

    int find(TreeNode* root, int k) {
        int left = leftCount[root];

        if (k == left + 1) {
            return root->val;  // 当前节点就是第 k 小
        } else if (k <= left) {
            return find(root->left, k);  // 在左子树中找第 k 小
        } else {
            return find(root->right, k - left - 1);  // 在右子树中找第 k - left - 1 小
        }
    }
};
```

**问题/优化方向**：
- 适用于需要多次查询的场景。如果只查询一次，预处理的开销不值得。

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 适用场景 |
|------|-----------|-----------|----------|
| 递归中序遍历 | O(H + k) | O(H) | **推荐**：单次查询，代码简洁 |
| 迭代中序遍历 | O(H + k) | O(H) | 单次查询，可自然提前终止 |
| 预处理 + 二分 | O(n) 预处理, O(H) 查询 | O(n) | **多次查询**时高效 |

# 关键要点

1. **BST 中序遍历的性质**：
   中序遍历（左 → 根 → 右）BST 会按**从小到大**的顺序输出节点值。这是 BST 的核心性质，是解决本题的基础。

2. **辅助变量的传递方式**：
   - **值传递** `int count`：每层递归有独立的副本，修改不会影响其他层
   - **引用传递** `int& count`：所有层共享同一个变量，修改会全局生效
   - **成员变量**：把 `count` 定义为类成员变量，也是一种共享方式

3. **辅助变量的更新位置**：
   - 前序位置（处理逻辑 → 左 → 右）：在访问子树前处理
   - 中序位置（左 → 处理逻辑 → 右）：在访问完左子树后处理
   - 后序位置（左 → 右 → 处理逻辑）：在访问完所有子树后处理

   本题需要中序位置更新计数器，因为要按从小到大的顺序计数。

4. **递归 vs 迭代**：
   - 递归代码简洁，但受系统栈大小限制
   - 迭代更复杂，但可以更精细地控制流程（如提前终止）

---

**推荐**：面试中使用**思路一（递归中序遍历）**，代码简洁、易理解。如果面试官要求提前终止优化，可以讨论迭代写法或添加标志位。如果是设计题，需要支持多次查询，可以讨论思路三的预处理方案。
