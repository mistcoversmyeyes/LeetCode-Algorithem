# 25. K 个一组翻转链表

## 题目描述

给你链表的头节点 `head` ，每 `k` 个节点一组进行翻转，请你返回修改后的链表。

`k` 是一个正整数，它的值小于或等于链表的长度。如果节点总数不是 `k` 的整数倍，那么请将最后剩余的节点保持原有顺序。

你不能只是单纯的改变节点内部的值，而是需要实际进行节点交换。

**示例 1**：
```
输入：head = [1,2,3,4,5], k = 2
输出：[2,1,4,3,5]
```

**示例 2**：
```
输入：head = [1,2,3,4,5], k = 3
输出：[3,2,1,4,5]
```

---

# 思路一：先翻转再翻回来（O(n+k)）

## 解题思路

**核心思想**：不管够不够 k 个，先全部翻转。最后一组如果不足 k 个，再翻转回来恢复原状。

这是我最自然的想法：直接翻转，不够就再翻回去。

**算法流程**：
1. 遍历链表，每 k 个节点进行翻转
2. 翻转后检查是否满足 k 个
3. 如果最后一组不足 k 个，再翻转一次恢复
4. 连接各组

## 复杂度
- 时间复杂度：O(n + k) — 每个节点翻转 1 次，最后一组最多 k 个节点翻 2 次
- 空间复杂度：O(1)

## Code
```cpp
// 伪代码思路
while (cur) {
    // 不管够不够，先翻转 k 个
    while (count < k && cur) {
        // 翻转操作
        count++;
    }
    if (count != k) {
        // 最后一组不够 k 个，再翻转回来
        // 反向翻转恢复
    }
    // 连接各组
}
```

**问题/优化方向**：
这个思路理论上时间复杂度更优（O(n+k) vs O(2n)），但实现起来逻辑复杂，容易出现指针错误。面试时如果时间充裕可以尝试，但标准答案通常是"先检测再翻转"。

# 思路二：先检测再翻转（✅ 推荐解法）

## 解题思路

**核心思想**：每次翻转前，先检测是否有足够的 k 个节点。如果不够，直接结束。

这是面试中更常见的标准做法。虽然理论复杂度是 O(2n)，但逻辑清晰，容易写对。

**算法流程**：
1. 使用 **dummy 节点**统一处理边界情况
2. 用 `before` 指向每组的前驱节点，`after` 指向每组的开始节点
3. **先检测**：从 `after` 开始往后数 k 个节点，判断是否足够
4. **再翻转**：如果够 k 个，翻转这组节点
5. **连接**：翻转后重新连接各组
6. **更新**：更新 `before` 和 `after`，继续下一组

## 关键指针示意

```
翻转前：
dummy →  1 → 2 → 3 → 4 → 5 → 6
  ↑      ↑
before after

翻转第一组后：
            更新 after = 4
                    ↓
dummy → 3 → 2 → 1 → 4 → 5 → 6
  ↑             ↑
before     更新 before = 1

翻转第二组后：
dummy → 3 → 2 → 1 → 6 → 5 → 4
                ↑           ↑
              before      after
```

## 复杂度
- 时间复杂度：O(n) — 每个节点被检查 1 次，满 k 的节点被翻转 1 次
- 空间复杂度：O(1)

## Code
```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;
 *     ListNode *next;
 *     ListNode() : val(0), next(nullptr) {}
 *     ListNode(int x) : val(x), next(nullptr) {}
 *     ListNode(int x, ListNode *next) : val(x), next(next) {}
 * };
 */
class Solution {
public:
    ListNode* reverseKGroup(ListNode* head, int k) {
        ListNode* dummy = new ListNode(-1, head);
        // 记录已经反转的链表的尾节点（前驱节点）
        ListNode* before = dummy;
        // 记录当前组的头节点（翻转后会变成这组的尾节点）
        ListNode* after = head;

        ListNode* pre = nullptr;
        ListNode* cur = head;

        while (true) {
            // 第一步：检测是否有 k 个节点
            ListNode* cursor = after;
            for (int i = 0; i < k; i++) {
                if (cursor == nullptr) {
                    // 不够 k 个，返回结果
                    return dummy->next;
                }
                cursor = cursor->next;
            }

            // 第二步：翻转 k 个节点
            cur = after;
            pre = before;
            for (int i = 0; i < k; i++) {
                ListNode* next = cur->next;
                cur->next = pre;
                pre = cur;
                cur = next;
            }

            // 第三步：连接各组
            after->next = cur;      // 原组首（现组尾）指向下一组
            before->next = pre;     // 前驱指向翻转后的组首

            // 第四步：更新 before 和 after
            before = after;         // before 移到当前组的尾
            after = cur;            // after 移到下一组的头
        }

        return dummy->next;
    }
};
```

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 先翻转再翻回来 | O(n + k) | O(1) | 理论上更优，但实现复杂，容易出错 |
| 先检测再翻转 | O(n) | O(2n) 实际也是 O(n) | O(1) | 逻辑清晰，面试推荐 |

# 关键词与核心洞察

## 关键词
- **dummy 哨兵节点**：消除边界情况，让第一组和后续组用统一的逻辑处理
- **循环不变量**：`before` 和 `after` 的语义在每次循环后保持一致
- **链表翻转**：LeetCode 206 的基础操作，内层循环就是标准的链表翻转

## 本题 Insight
- **dummy 节点的本质**：不是"多加一个节点"，而是"消除特殊情况"。有了 dummy，第一组就有前驱节点，不需要 `if (before == nullptr)` 的特殊判断
- **"先检测再翻转"的价值**：虽然理论上复杂度更高，但代码清晰度更重要。面试时能快速写出正确的逻辑，比追求微小的性能优化更有价值

## 易错点
- `before` 和 `after` 的更新顺序：先更新 `before = after`（指向翻转后的组尾），再更新 `after = cur`（指向下一组的头）
- 内层翻转的循环边界：必须是 `i < k`，翻转恰好 k 个节点
- 检测循环和翻转循环的分离：检测时不能修改链表结构，翻转时才修改
