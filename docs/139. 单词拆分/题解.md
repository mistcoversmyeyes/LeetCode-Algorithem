**139.** 单词拆分 - 题解
====

# 题目描述

给你一个字符串 `s` 和一个字符串列表 `wordDict` 作为字典。如果可以利用字典中出现的一个或多个单词拼接出 `s` 则返回 `true`。

**注意：**不要求字典中出现的单词全部都使用，并且字典中的单词可以重复使用。

**示例 1：**
```
输入: s = "leetcode", wordDict = ["leet", "code"]
输出: true
解释: 返回 true 因为 "leetcode" 可以由 "leet" 和 "code" 拼接成。
```

**示例 2：**
```
输入: s = "applepenapple", wordDict = ["apple", "pen"]
输出: true
解释: 返回 true 因为 "applepenapple" 可以由 "apple" "pen" "apple" 拼接成。
注意，你可以重复使用字典中的单词。
```

# 思路一：递归 + 记忆化（字符串作为 key）

## 解题思路
**核心思想**：对于字符串 `s`，尝试所有可能的前缀单词，对剩余后缀递归判断。

这是我最初的思路：
- 遍历所有前缀，检查是否在字典中
- 如果在，对剩余后缀递归调用
- 用哈希表缓存已计算过的字符串结果

**算法流程**：
1. 检查 `s` 是否为空，空字符串返回 true（可拆分成零个词）
2. 遍历 `s` 的所有前缀
3. 如果前缀在字典中，对后缀递归
4. 缓存结果避免重复计算

## 复杂度
- 时间复杂度：O(n² × m)，n 为字符串长度，m 为单词查找时间
- 空间复杂度：O(n³)，字符串作为 key，存储开销大

## Code
```cpp
class Solution {
public:
    bool wordBreak_memo(string s, unordered_set<string>& words, unordered_map<string, bool>& memo) {
        if (memo.count(s)) return memo[s];  // 命中缓存
        if (s.empty()) return true;          // 空串可拆分

        for (int i = 0; i < s.length(); i++) {
            string prefix = s.substr(0, i + 1);
            string suffix = s.substr(i + 1);
            if (words.count(prefix) && wordBreak_memo(suffix, words, memo)) {
                return memo[s] = true;
            }
        }
        return memo[s] = false;
    }

    bool wordBreak(string s, vector<string>& wordDict) {
        auto words = unordered_set<string>(wordDict.begin(), wordDict.end());
        auto memo = unordered_map<string, bool>();
        return wordBreak_memo(s, words, memo);
    }
};
```

**问题/优化方向**：
- 字符串作为 key，每次查找都要计算哈希，开销大
- 每次 `substr` 创建新字符串，效率低
- **实测**：47ms，只 beats 6.97%

# 思路二：递归 + 记忆化（索引作为 key）

## 解题思路
**核心思想**：用索引代替字符串作为缓存的 key，避免字符串拷贝和哈希计算。

我一开始不理解为什么记忆化有效：
> "我感觉这题它不像斐波那契数列那样有很多交叠的子问题啊"

**关键洞察**：较短的后缀往往被多个较长的后缀依赖。计算 `s[0:]` 时可能需要计算 `s[3:]`，而计算 `s[1:]` 时可能又需要计算 `s[3:]`，这就产生了重复。

**算法流程**：
1. 用 `start` 表示当前处理到的位置
2. 检查 `start == s.length()` 作为终止条件
3. 从 `start` 开始扫描所有可能的单词
4. 用 `vector<int>` 作为缓存，下标访问 O(1)

## 复杂度
- 时间复杂度：O(n²)
- 空间复杂度：O(n)，索引数组

## Code
```cpp
class Solution {
    vector<int> memo;  // -1: 未计算, 0: false, 1: true
    unordered_set<string> wordSet;

    bool dfs(int start, string& s) {
        if (start == s.length()) return true;        // 到末尾了
        if (memo[start] != -1) return memo[start];   // 已计算过

        for (int end = start + 1; end <= s.length(); end++) {
            string word = s.substr(start, end - start);  // 从 start 取 end-start 个字符
            if (wordSet.count(word) && dfs(end, s)) {
                return memo[start] = true;
            }
        }
        return memo[start] = false;
    }

public:
    bool wordBreak(string s, vector<string>& wordDict) {
        memo.assign(s.size(), -1);
        wordSet = unordered_set<string>(wordDict.begin(), wordDict.end());
        return dfs(0, s);
    }
};
```

**问题/优化方向**：无，这是推荐解法。

# 思路三：自底向上 DP

## 解题思路
**核心思想**：`dp[i]` 表示 `s[0:i]` 是否可以拆分，从小问题递推到大问题。

**状态转移**：
- `dp[i] = true` 当存在 `j < i`，使得 `dp[j] = true` 且 `s[j:i]` 在字典中

**算法流程**：
1. 初始化 `dp[0] = true`（空串可拆分）
2. 外层循环遍历结束位置 `i`
3. 内层循环遍历起始位置 `j`
4. 如果 `dp[j]` 为真且 `s[j:i]` 在字典中，则 `dp[i] = true`

## 复杂度
- 时间复杂度：O(n²)
- 空间复杂度：O(n)

## Code
```cpp
bool wordBreak(string s, vector<string>& wordDict) {
    unordered_set<string> wordSet(wordDict.begin(), wordDict.end());
    vector<bool> dp(s.size() + 1, false);
    dp[0] = true;  // 空串可拆分

    for (int i = 1; i <= s.size(); i++) {
        for (int j = 0; j < i; j++) {
            if (dp[j] && wordSet.count(s.substr(j, i - j))) {
                dp[i] = true;
                break;  // 找到一个可行拆分即可
            }
        }
    }
    return dp[s.size()];
}
```

**问题/优化方向**：最简洁的实现，避免递归开销。

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 字符串 key 记忆化 | O(n² × m) | O(n³) | 直观但效率低 |
| 索引 key 记忆化 | O(n²) | O(n) | 推荐写法 |
| 自底向上 DP | O(n²) | O(n) | 最简洁 |

# 关键词与核心洞察

## 关键词
- **记忆化搜索**：避免重复计算相同子问题，用空间换时间
- **动态规划**：从小问题递推到大问题，`dp[i]` 依赖 `dp[j]` (j < i)
- **字符串哈希**：用哈希集合存储字典，O(1) 查找单词

## Insight
- **记忆化有效的本质**：较短的后缀被多个较长的后缀依赖。比如 `s = "abcabc"`，计算 `s[0:]` 和 `s[3:]` 都可能需要计算 `s[3:]` 和 `s[6:]`。
- **索引 vs 字符串作为 key**：索引访问 O(1)，字符串哈希计算 O(n)，效率差距明显

## 易错点
- **终止条件**：检查 `start == s.length()`，不是 `s.empty()`（因为 `s` 是引用传递，不会变空）
- **substr 参数**：`s.substr(pos, len)` 第二个参数是**长度**，不是结束位置
- **变量命名**：循环变量不要和函数参数同名，会被覆盖
- **prefix 计算**：从当前位置 `start` 开始取，不是从 0

---

**推荐**：面试中使用**思路三（自底向上 DP）**，代码最简洁，思路最清晰。如果需要解释记忆化，可以用**思路二**演示。
