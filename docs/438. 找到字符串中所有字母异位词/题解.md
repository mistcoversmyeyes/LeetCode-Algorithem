# 438. 找到字符串中所有字母异位词 - 题解

## 题目描述

给定两个字符串 `s` 和 `p`，需要在 `s` 中找到所有是 `p` 的字母异位词的子串，返回这些子串的起始下标。

例如：
```text
输入: s = "cbaebabacd", p = "abc"
输出: [0, 6]
```

---

# 思路一：暴力枚举所有长度为 k 的子串

## 解题思路
**核心思想**：既然字母异位词的长度一定和 `p` 相同，那我只需要枚举所有长度为 `k = |p|` 的子串，然后对每个子串排序后和 `p` 排序后的结果比较。

这是我一开始最自然的想法。最开始我甚至会说“枚举所有子串”，但后来很快意识到：这题真正需要关心的，其实只有长度和 `p` 一样的窗口。

**算法流程**：
1. 先将 `p` 排序，作为比较基准。
2. 枚举 `s` 中所有长度为 `k` 的子串。
3. 对当前子串排序，如果和排序后的 `p` 相同，就记录当前左端点。

## 复杂度
- 时间复杂度：`O((n - k + 1) * k log k)`，每个窗口都要重新排序。
- 空间复杂度：`O(k)`，用于存放当前子串副本。

## Code
```cpp
class Solution {
public:
    vector<int> findAnagrams(string s, string p) {
        vector<int> ans;
        int n = s.size(), k = p.size();
        if (n < k) return ans;

        string target = p;
        sort(target.begin(), target.end());

        for (int i = 0; i + k <= n; i++) {
            string cur = s.substr(i, k);
            sort(cur.begin(), cur.end());
            if (cur == target) {
                ans.push_back(i);
            }
        }

        return ans;
    }
};
```

**问题/优化方向**：问题不只是“枚举很多窗口”，更大的问题是每个窗口都要重新做一次完整统计，重复计算太多。

---

# 思路二：定长滑窗 + `unordered_map` 计数（❌ 实现阶段踩坑很多）

## 解题思路
**核心思想**：既然窗口长度固定，那就不要每次重新统计整个子串，而是维护“当前窗口内每个字符出现次数”，窗口右移一格时，只更新移出的字符和移入的字符。

这是我从暴力法往下优化时最先想到的版本：用滑动窗口遍历所有长度为 `k` 的候选子串，再用哈希表记录字符频次。

**算法流程**：
1. 先统计 `p` 中每个字符出现的次数。
2. 初始化第一个长度为 `k` 的窗口，并统计窗口内字符次数。
3. 比较当前窗口频次和 `p` 的频次是否相同。
4. 窗口右移一格时，减少左端字符频次，增加新右端字符频次。

## 复杂度
- 时间复杂度：平均为 `O(n)`，但实现上需要额外注意哈希表比较和维护细节。
- 空间复杂度：`O(字符种类数)`。

## Code
```cpp
// 这是思路方向，不是最终推荐实现。
// 真正的问题不在“滑窗方向”本身，而在实现细节很容易乱。
unordered_map<char, int> win, need;
```

**问题/优化方向**：这个版本让我真正意识到滑动窗口的难点不在“想到滑窗”，而在“循环不变量能不能始终维护住”。这次我踩到的坑主要有：
- 初始化窗口时少统计了一个字符。
- 统计 `p` 的频次时，误操作到了窗口 map。
- 窗口右移时，下标更新顺序和窗口状态没有同步。
- 某个字符计数减到 `0` 以后，`unordered_map` 里的键还在，直接用 `map1 == map2` 会出错。
- 最后一个合法窗口很容易被漏检。
- 我一度把更新窗口的 lambda 写成值传递，结果外面的窗口状态根本没更新。

这一步虽然没有成为最终写法，但它逼着我把“循环不变量”想清楚了：进入循环时，`[i, j]` 必须已经是一个长度固定的合法窗口，而且维护的数据结构必须准确对应 `s[i..j]` 的状态。

# 思路三：定长滑窗 + `vector<int>(26)`（✅ 推荐解法）

## 解题思路
**核心思想**：题目只包含小写字母，所以没必要用哈希表，直接用两个长度为 `26` 的计数数组表示 `p` 和当前窗口的字符频次。窗口每次右移一格，只更新两个字符，比较两个数组是否相等即可。

这是最后真正通过 OJ 的版本。相比 `unordered_map`，`vector<int>(26)` 的优势非常直接：

**算法流程**：
1. 如果 `s.size() < p.size()`，直接返回空数组。
2. 用 `need[26]` 统计 `p` 的字符频次。
3. 用 `window[26]` 统计 `s` 的第一个长度为 `k` 的窗口。
4. 进入循环时，保证 `[i, j]` 是一个完整合法的定长窗口，并且 `window` 精确表示 `s[i..j]` 的字符频次。
5. 先判断当前窗口是否匹配；如果匹配，就把 `i` 加入答案。
6. 如果后面还有下一个窗口，就让左端字符计数减一、右端新字符计数加一，然后滑到下一个窗口。

## 复杂度
- 时间复杂度：`O(n)`。
  初始化频次数组是 `O(k)`，一共有 `n - k + 1` 个窗口，每次移动窗口只更新两个字符，比较两个长度为 `26` 的数组是常数时间。
- 空间复杂度：`O(1)`。
  两个长度为 `26` 的数组，字母表大小固定。

## Code
```cpp
class Solution {
public:
    vector<int> findAnagrams(string s, string p) {
        if (s.length() < p.length()) {
            return vector<int>();
        }


        auto ans = vector<int>();
        int k = p.length();
        vector<int> window(26, 0);
        vector<int> need(26, 0);

        int i = 0;
        int j = i + k - 1;
        
        // 初始化 p 包含的各个字母的数量
        for (int m = 0; m < k; m++) {
            need[p[m] - 'a']++;
        }
        // 初始化第一个窗口的状态
        for (int m = 0; m < k; m++) {
            window[s[m] - 'a']++;
        }

        // 循环不变量：
        // - 进入循环时 i..=j 这个窗口对应一个长度为 p.length() 的窗口。
        // - 窗口关联到的状态信息准确对应该窗口。
        while (j < s.length()) {
            auto to_update = [] (vector<int>& win, vector<int>& need){
                return win == need;
            };
            // 第一部分：检查候选窗口，判断是否要更新答案。
            if (to_update(window, need)) {
                ans.push_back(i);
            }
            // 第二部分：获取下个待搜索窗口，并更新下个窗口对应的状态信息。
            i++;
            j++;
            if (j == s.length())    break; 
            [&] (vector<int>& win){
                win[s[i - 1] - 'a']--;
                win[s[j] - 'a']++;
            }(window);
        }

        return ans;
    }
};
```

**问题/优化方向**：这个版本已经够用了。如果面试官继续追问，还可以再优化“每次比较整个 26 长数组”这一步，用一个 `diff` 或 `mismatch` 计数进一步减少比较成本，但这题没有必要强上。

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 暴力枚举 + 排序比较 | `O((n-k+1) * k log k)` | `O(k)` | 直观，但重复计算太多 |
| 定长滑窗 + `unordered_map` | 平均 `O(n)` | `O(字符种类数)` | 方向正确，但实现细节很容易错 |
| 定长滑窗 + `vector<int>(26)` | `O(n)` | `O(1)` | 最稳，最贴合题目数据范围 |

# 关键词与核心洞察

## 关键词
- **定长滑动窗口**：这题不是“枚举所有子串”，而是只枚举所有长度为 `k` 的候选窗口。长度约束本身就是第一层剪枝。
- **状态复用**：滑窗真正节省时间的地方，不是窗口这个形式本身，而是可以复用上一个窗口的状态，只增量更新两个字符。
- **循环不变量**：进入循环时，当前窗口必须已经是合法窗口，且维护的数据结构必须准确表示当前窗口状态。窗口对了但状态错了，答案照样会错。
- **空间换时间**：用两个长度为 `26` 的计数数组换掉重复统计，是这题从暴力法降到线性时间的关键。

## Insight
这题让我对滑动窗口的理解更具体了一层。滑动窗口不只是“两个指针一起移动”，真正重要的是两件事：

1. `while` 条件只负责描述“当前这一轮在什么前提下成立”。
2. 真正的循环不变量，还要靠循环体结尾的更新逻辑去维护。

对定长滑窗来说，这个不变量可以说成一句很硬的话：

进入循环时，`[i, j]` 必须已经是一个长度固定的有效窗口，并且窗口计数结构精确对应 `s[i..j]`。

一旦这句话在代码里没有被维护住，就会出现各种熟悉的 bug：初始化少一个字符、更新顺序错、最后一个窗口漏检、状态数组没有真的同步更新。

## 易错点
- 题目要求的是字母异位词，所以候选子串长度必须和 `p` 完全相同，不需要枚举所有长度。
- 窗口右移时，更新的是“移出的旧左端字符”和“移入的新右端字符”，不是随便改两个下标。
- 如果循环里先更新下标，再不加判断地访问新位置，很容易在最后一个窗口后越界。
- 用 `unordered_map` 时，字符频次减到 `0` 后键还留在 map 里，直接比较两个 map 容易出问题。
- 用 lambda 更新窗口状态时，如果参数是值传递，外部状态根本不会被修改。

---

**推荐**：面试中使用**思路三：定长滑窗 + `vector<int>(26)`**，因为它最贴合“小写字母”这个数据范围，表达清楚、复杂度稳定，而且最容易把循环不变量讲严谨。
