# 35. 搜索插入位置 - 题解

## 题目描述

给定一个排序数组和一个目标值，在数组中找到目标值，并返回其索引。如果目标值不存在于数组中，返回它将会被按顺序插入的位置。

请必须使用时间复杂度为 `O(log n)` 的算法。

**示例 1：**
```
输入: nums = [1,3,5,6], target = 5
输出: 2
```

**示例 2：**
```
输入: nums = [1,3,5,6], target = 2
输出: 1
```

**示例 3：**
```
输入: nums = [1,3,5,6], target = 7
输出: 4
```

---

# 思路一：三分支递归二分查找（✅ 推荐解法）

## 解题思路

**核心思想**：维护一个不变式（invariant），让代码的 base case 可以直接返回答案，无需额外判断。

我最初的想法是用递归来实现二分查找，但不同于常见的 lower_bound 写法，我选择了**三个分支**（`<`、`=`、`>`）的递归策略。

**关键洞察——不变式（Invariant）**：

每次进入递归时，保证以下性质成立：
- `[0, left-1]` 区间的所有值都 **小于** `target`
- `[right+1, n-1]` 区间的所有值都 **大于** `target`

当递归到达 base case（`left > right`）时，两个区间"碰头"了：
- `left` 是右区间的起点（`right + 1`）
- `left` 左边的所有值都 `< target`
- `left` 右边的所有值都 `> target`

**因此 `left` 恰好就是插入位置！**

**算法流程**：
1. 计算 `mid = (left + right) / 2`
2. 如果 `target < nums[mid]`：递归左半部分，`right = mid - 1`
3. 如果 `target > nums[mid]`：递归右半部分，`left = mid + 1`
4. 如果 `target == nums[mid]`：直接返回 `mid`
5. Base case：`left > right` 时返回 `left`

## 复杂度
- 时间复杂度：O(log n) —— 每次将搜索范围减半
- 空间复杂度：O(log n) —— 递归栈深度

## Code
```cpp
class Solution {
public:
    int searchInsert_recursion(vector<int>& nums, int target, int left, int right) {
        // Base case：当 left > right 时，left 就是插入位置
        // 因为 invariant 保证 [0, left-1] < target 且 [right+1, n-1] > target
        // 而 right + 1 == left，所以 left 左边都小于 target，右边都大于 target
        if (left > right) {
            return left;
        }

        int mid = (right + left) / 2;

        if (target < nums[mid]) {
            // 目标在左半部分，right 收缩到 mid-1
            // 不变式依然成立：[right+1, n-1] = [mid, n-1] 都 > target
            return searchInsert_recursion(nums, target, left, mid - 1);
        }
        else if (target == nums[mid]) {
            // 找到目标，直接返回
            return mid;
        }
        else {
            // 目标在右半部分，left 收缩到 mid+1
            // 不变式依然成立：[0, left-1] = [0, mid] 都 < target
            return searchInsert_recursion(nums, target, mid + 1, right);
        }
    }

    int searchInsert(vector<int>& nums, int target) {
        return searchInsert_recursion(nums, target, 0, nums.size() - 1);
    }
};
```

**为什么选三分支？**

这是 Linus Torvalds "好品味"的体现——**让特殊情况消失，而不是增加条件判断**。

- 二分支（`<` 和 `>=`）需要额外处理 `==` 时是否继续左移、base case 需判断是"找到"还是"未找到"、还要处理越界
- 三分支把 `==` 单独拎出来，base case 直接返回 `left`，**没有任何特殊情况**

# 思路二：二分支递归（lower_bound 思路）（❌ 探索后放弃）

## 解题思路

**核心思想**：将 `<` 和 `==` 合并，只保留两个分支。

我探索了另一种写法：
```cpp
if (target <= nums[mid]) {
    right = mid;  // 包含 mid
} else {
    left = mid + 1;
}
```

这种写法试图找到"第一个 ≥ target 的位置"，也就是 lower_bound。

**遇到的问题**：

1. **死循环风险**：当 `right = mid` 且 `left` 和 `right` 相邻时
   - `mid = (left + right) / 2 = left`
   - 如果继续 `right = mid`，就会陷入死循环
   - 必须改用 `while (left < right)` 和防溢出的 `mid = left + (right - left) / 2`

2. **base case 复杂**：`left == right` 时还需判断：
   - `nums[left] == target`？返回 `left`
   - `nums[left] > target`？返回 `left`（插入位置）
   - 还要处理 `target` 比所有元素都大的越界情况

3. **不变式更复杂**：区间右端点需要包含 `n` 而不是 `n-1`

**结论**：虽然二分支在迭代写法中很优雅，但在递归中需要更多边界处理，不如三分支清晰。

## Code（参考，未采用）
```cpp
// 二分支写法示例（递归版，需要额外处理）
int searchInsert_lower_bound(vector<int>& nums, int target, int left, int right) {
    // 注意：right 初始化为 nums.size()，不是 nums.size() - 1
    if (left == right) {
        // 还需判断 nums[left] 与 target 的关系
        return left;
    }
    int mid = left + (right - left) / 2;  // 防溢出
    if (target <= nums[mid]) {
        return searchInsert_lower_bound(nums, target, left, mid);
    } else {
        return searchInsert_lower_bound(nums, target, mid + 1, right);
    }
}
```

# 思路三：迭代二分查找（工程实际使用）

## 解题思路

**核心思想**：同样的三分支逻辑，改成迭代实现，避免递归栈溢出风险。

在实际工程中，递归二分查找几乎不用。迭代写法使用同样的 invariant，代码更简洁高效。

## 复杂度
- 时间复杂度：O(log n)
- 空间复杂度：O(1) —— 只用了常数额外空间

## Code
```cpp
class Solution {
public:
    int searchInsert(vector<int>& nums, int target) {
        int left = 0, right = nums.size() - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;  // 防溢出

            if (target < nums[mid]) {
                right = mid - 1;
            } else if (target > nums[mid]) {
                left = mid + 1;
            } else {
                return mid;  // 找到目标
            }
        }

        // left > right 时，left 就是插入位置
        // invariant: [0, left-1] < target && [right+1, n-1] > target
        // 且 right + 1 == left，所以 left 是答案
        return left;
    }
};
```

# 总结对比

| 思路 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 三分支递归 | O(log n) | O(log n) | 代码清晰，invariant 直接导出 base case |
| 二分支递归 | O(log n) | O(log n) | 需要额外处理边界情况，复杂度高 |
| 三分支迭代 | O(log n) | O(1) | 工程实际使用，同样清晰无特殊情况 |

**推荐**：面试中可使用**三分支递归**展示对 invariant 的理解，但实际工程中应使用**三分支迭代**。

# 关键词与核心洞察

## 关键词
- **不变式（Invariant）**：每次进入递归的时候有 `[0, left-1] < target` 且 `[right+1, n-1] > target`。这不是事后验证，而是设计的起点。有了这个 invariant，base case 的答案自然显现。
- **好品味（Good Taste）**：Linus 的哲学——"让特殊情况消失"。三分支不是"笨"，而是把 `==` 单独处理，让 `left > right` 时直接返回 `left`，无需额外判断。
- **边界收缩**：`right = mid - 1`（不包含 mid）vs `right = mid`（包含 mid）。前者配合三分支，后者用于 lower_bound，各有适用场景。

## Insight

**二分查找的本质不是"找"，而是"缩小范围的同时保持性质"**。

很多人记住二分查找的模板代码，但不理解为什么 base case 返回 `left`。真正的理解来自 invariant——每次迭代/递归时，你维护了一个"不变的事实"。当范围缩到不能再缩时，这个不变的事实直接告诉你答案在哪。

**为什么三分支优于二分支（对于这个特定问题）**？

- 二分支试图"通用化"，把 `==` 融入 `<=`，但代价是：
  - 需要理解 lower_bound 的语义（找第一个 ≥ target）
  - base case `left == right` 时还需判断是"找到"还是"应该插入"
  - 需要处理越界（`target` 比所有元素大）

- 三分支"显式化"特殊情况，`==` 直接返回，`left > right` 直接返回 `left`，**没有任何隐含的特殊情况需要记忆**。

这正是 Linus 所说的："有时你可以从不同角度看问题，重写它让特殊情况消失，变成正常情况。"

**递归设计原则：把复杂度推向递归 case，base case 必须简单**

从这个二分查找的分析中，可以提炼出一个通用的递归设计原则：

- **二分支**把 `==` 的判断推迟到 base case，增加了 base case 的复杂度（需要判断是"找到"还是"应该插入"）
- **三分支**在递归 case 就处理掉 `==`，base case 只需 `return left`

这适用于所有递归算法设计：
- base case 应该是"显而易见"的正确
- 所有条件判断尽量在递归 case 中完成
- 如果 base case 需要多个 if 分支，考虑把某些分支上移到递归 case

> 好的递归算法，base case 一定是非常简单的。

## 易错点
- **整数溢出**：`mid = (left + right) / 2` 在 `left` 和 `right` 很大时可能溢出。应使用 `mid = left + (right - left) / 2`。
- **递归边界**：`left` 和 `right` 的初始值要配对。如果 `right = nums.size() - 1`，循环条件是 `<=`，base case 是 `left > right`；如果 `right = nums.size()`，循环条件是 `<`，base case 是 `left == right`。
- **返回值的语义**：想清楚返回 `left` 还是 `right`。在三分支 invariant 下，`left` 始终是"第一个可能的位置"，`right` 是"最后一个不可能的位置"，所以答案是 `left`。

**推荐**：深入理解 invariant 后，面试中可以从容选择三分支（展示理解）或二分支 lower_bound（展示熟练度）。实际工程代码推荐**三分支迭代**。
